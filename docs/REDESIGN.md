### 1.3 数据模型（不可破坏）

```
subject   { id, name, fullScore, color, hidden, sortOrder }
record    { id, subjectId, paperName, recordType: paper|exercise|composite,
            paperVariant: true|mock, score, fullScore, date, durationMinutes,
            exerciseBookName, exercisePage, exerciseQuestion,
            note, pendingSync, createdAt, ... }
mistake   { id, subjectId, title, knowledgePoint, analysis, status, difficulty,
            sourceRecordId, questionText, nextReviewAt, reviewedAt,
            createdAt, updatedAt }
image     { id, ownerType, ownerId, name, size, storageKey, url, pendingUpload, uploadError }
```

错题状态枚举：`待复盘 / 不熟 / 不会 / 已整理 / 已掌握`；难度：`简单 / 中等 / 困难`。

### 1.4 现状问题

1. **样式层失控**：`main.css` 7682 行里叠了 4 套以上主题层，反复覆盖同一批选择器，改一处要靠 `!important` 抢优先级。
2. **信息架构平铺**：侧栏 6 个入口无分组，「同步」和「备份」与业务页同级，缺少「复盘」这一条主线。
3. **首页堆砌**：统计数字 + 焦点 + 提醒 + 快捷入口 + 2 个图表，模块之间没有主次，缺少「一眼看到进度」的核心面板。
4. **移动端入口过多**：底部导航塞了 6 项，拥挤。
5. **状态缺失**：加载态只有一句「正在加载本地学习档案...」，没有 skeleton；错误态基本没有；删除用 `window.confirm`。
6. **反馈不统一**：有的用 inline alert，有的用 Toast，有的什么都不给。

掌握状态用色：`已掌握 = green`、`已整理 = blue`、`不熟 = orange`、`不会 = red`、`待复盘 = muted`。

### 4.2 圆角 / 阴影 / 间距

- 圆角：`--r-sm 6px`、`--r-md 10px`、`--r-lg 14px`、`--r-pill 999px`。卡片用 `md`，弹窗用 `lg`，**不做大圆角**。
- 阴影：`--shadow-xs`（卡片默认）、`--shadow-sm`（hover）、`--shadow-md`（弹窗）。均为低透明度单层投影。
- 间距刻度：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40`。
- 栅格：桌面 12 列（`gap 16px`），内容最大宽度 `1200px`；平板 8 列；移动 4 列。

### 4.3 字号与字重

| 用途 | 字号 | 字重 |
| --- | --- | --- |
| 页面标题 | 22px | 700 |
| 模块标题 | 15px | 600 |
| 指标数值 | 26px | 700 |
| 正文 | 14px | 400 |
| 辅助说明 | 12px | 400 |
| 标签 | 12px | 600 |

### 4.4 断点

沿用现有约定，不再新增：

- `≤ 460px` 小屏手机
- `≤ 767px` 手机
- `768 – 1023px` 平板竖屏
- `1024 – 1180px` 平板横屏
- `≥ 1181px` 桌面

### 4.5 组件规范

统一由 `design-system.css` 定义：按钮（primary / secondary / ghost / danger，四态齐全）、输入框（默认/聚焦/错误/禁用）、下拉、标签、进度条、表格、卡片、弹窗、Toast、骨架屏、空状态。

### 首页（DashboardPage）

按八块重构：欢迎区（问候语随时段变化）→ 今日待办（到期错题 / 今日是否已记录 / 备份时效，全部由真实数据推导）→ 顶部筛选（科目 + 时间范围，作用于整页并写入 localStorage）→ 核心指标 → 快速录入 → 科目掌握度（练习进度 / 平均分 / 得分率 / 错题数 + 五态分布条）→ 学习贡献热力图 + 提醒 + 快捷入口 → 分数趋势 → 最近成绩。

明确没有做的事：没有编造「今日目标」，没有做收藏功能——这些在现有数据里没有依据，宁可空着也不塞假数据。

### 热力图（ContributionHeatmap）

- 原生 `title` 换成自绘 tooltip（桌面 hover）+ 常驻读数行（触屏点按），因为 `title` 在 iPad 上根本弹不出来。
- 每天统计成绩条数、错题条数、成绩里记录的用时；没记用时就是「未记录用时」，不猜。
- 加了月份刻度；移动端横向滚动并在挂载后自动滚到最右（最近的日子）。

### 成绩图表（ScoreCharts）

- 支持时间范围筛选（`rangeDays`，0 = 全部）。
- 颜色从设计 token 读取，不再散落硬编码色值。
- 两个面板各自独立初始化：某个面板没数据被 `v-if` 掉时，另一个照常渲染，且容器消失时会销毁对应实例。
- 用 `ResizeObserver` 适配侧栏在「图标条 / 抽屉」之间切换导致的宽度变化。

### 错题连续复习

- 列表页：状态 chip（带各状态数量，点一下即筛选）、搜索 / 科目 / 章节（复用 `knowledgePoint`）/ 难度 / 排序全部即时生效，筛选条件写入 URL query。
- 详情页：上一题 / 下一题沿用列表页的筛选与排序（条件通过 query 带过去），所以「筛出 5 道不熟的题」就能顺着这 5 道翻完；状态可就地切换；桌面端支持 `←` `→` 翻题、`1`–`5` 切状态。
- 复习日志只写 localStorage，不改动 IndexedDB 里的错题结构。

### 交互与表单

- 6 处 `window.confirm` 全部替换为站内确认弹窗（`useConfirm()`），删除后的成功提示沿用 store 里已有的 toast。
- 成绩页筛选改为即时生效：下拉一改就应用，关键词输入 260ms 防抖。同步筛选时不再顺手收起录入面板，避免打断正在填的表单。
- 桌面端顶栏吸顶；底部标签栏从 6 项精简为 5 项（总览 / 成绩 / 错题 / 科目 / 备份），同步入口保留在顶栏账号区。
- 侧栏导航按「学习 / 管理」分组；详情页里侧栏选中态自己判定（路由是扁平注册的，`router-link-active` 不会把 `/records` 认成 `/records/123` 的父级）。

### 2. `scripts/prune-css.mjs`：安全剪掉死样式

上面这轮替换让 `records-hero`、`records-metric`、`summary-grid`、`detail-head`、`detail-copy`、`subject-detail-panel` 等一批类彻底失去引用。
直接手删 7800 行的 CSS 风险太高，所以写了个剪枝器：

- **不做自动推断**。模板里存在 `preview-cell-${fieldId}`、`is-${tone}`、`tone-${tone}` 这类拼接类名，
  「CSS 里定义了但 .vue 里搜不到」并不等于死类，自动推断一定会误删。死类清单必须显式给出。
- 选择器列表按顶层逗号拆开，**只摘掉命中死类的那些选择器**；只要还剩一个活的，规则就保留。
- 递归进入 `@media / @supports / @layer / @container`，块内全空才整块丢。
- 扫描时跳过注释与字符串，规则前的注释单独留存，不会因为规则被删而丢掉章节分隔说明。

结果：`main.css` 7839 → 7631 行、`design-system.css` 2946 → 2916 行，共丢 39 条规则、摘除 130 个选择器，
CSS 产物 162.4 kB → 157.5 kB。

验证方式不是「看着没问题」，而是**拿剪枝前的 49 张截图做哈希比对**：
剪枝前后 10 张有差异，但同一份代码连跑两次也有 6~8 张差异，且差异全部集中在带列表的错题页——
逐张看过，布局、间距、颜色、字号完全一致，只是列表首条卡片不同（数据顺序），所以判定为非回归。

### 3. 顺手修掉错题排序的不确定性

`filterAndSortMistakes` 的四个比较函数都没有兜底键。`createdAt` 相同时（批量导入、同一天连续录入很常见）

## 第三轮：首页减负 + 导出入口 + 按钮实测

用户反馈三件事：首页太长、「科目掌握度」那四张卡很突兀、找不到导出按钮，另外怀疑有按钮是摆设。

### 1. 首页从 10 块压到 6 块常驻

| 改前 | 改后 |
| --- | --- |
| 欢迎区、今日待办分成两块 | 合并为一个 `.ds-welcome-block` |
| 科目掌握度（四张科目卡 + 五态分布条） | **整块移到 `/subjects`**，改名「掌握概览」 |
| 学习贡献热力图（屏高很大） | 默认折叠，点标题展开，展开状态存 localStorage |

| 最近成绩 6 条 | 8 条 |

常驻区块：欢迎区（含待办）→ 筛选 → 指标卡 → 最近成绩 → 分数趋势 → 提醒 + 快捷入口。

`<div role="button" tabindex="0">` + Enter/Space 键盘支持，没有硬塞成 button。

### 2. 导出按钮的可发现性

导出成绩（Excel）本来只存在于成绩页顶部，而首页「快捷入口」里放的是「导出 JSON」——
那是整站备份，跟成绩导出不是一回事，名字却很像，所以用户找不到。

- 首页快捷入口新增「导出成绩 Excel」，直接调 `exportRecordsToExcel` 导出全部成绩（一步到位，
  不弹配置面板；要挑字段、按卷子分列仍去成绩页的导出面板）。
- 原有两个入口改名：`导出 JSON` → **备份全部数据**、`合并导入` → **恢复备份**。

### 3. `scripts/audit-buttons.mjs`：把每个按钮真的点一遍

静态扫过：全站 138 个 `<button>` 都绑了事件，也没有「敬请期待 / 开发中」这类占位文案，
所以「摆设 UI」的怀疑不成立。真正会出问题的是**点了没反应 / 点了报错 / 点了把界面搞坏**，
这个只能真点。脚本要点：

- 每点一个按钮前**重新加载页面**：状态天然干净，不用写复原逻辑；危险操作即使弹出了确认框，
  重载也会丢弃，不会真的删数据。
- 点击前后各取一次签名（路由、文字哈希、弹窗数、Toast 数、可见按钮数、主题属性），
  用来判断「到底有没有发生什么」。**主题属性必须带上**，否则「跟随系统/浅色/深色」
  只改属性不改文字，会被误判成无反应。
- 按钮选择器是 `button, [role="button"]`——折叠开关是 role=button 的 div，只扫 `<button>` 会漏。
- 文件类按钮（合并导入 / 恢复备份 / 覆盖恢复）会拉起系统选择框，DOM 上没有任何变化。
  用 Playwright 的 `filechooser` 事件喂一个**结构合法但内容为空**的备份：JSON.parse 能过，
  确认框会正常弹出，路径被真正走到；内容为空且脚本永不点「确认」，所以不会改到测试数据。

**实测结果：72 个按钮，0 报错，没有危险操作漏掉确认。**
5 个「无可见变化」逐个核对过，都是合理无反馈：状态 chip 点的是当前已选状态、
错题状态按钮点的是当前已是该状态、科目名称为空时提交被表单校验挡下、登录页分段控件点的是当前模式。

### 4. 顺手修掉的两个真 bug

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 错题详情「完成本次复习」在题目已是「已掌握」时**完全没反应** | `markReviewed` 直接调 `setStatus("已掌握")`，而 `setStatus` 遇到状态未变会 `return`。于是「已掌握的题再复习一遍」——间隔重复里最常见的场景——不计复习次数、不更新复习时间、连 toast 都没有 | 改成无论状态是否变化都记一次复习，并按情况给不同文案 |
| 备份页「覆盖恢复」**没有任何二次确认** | `onImport` 解析完文件直接 `importData(payload, false)`，而覆盖恢复会清掉全部成绩、错题、图片和科目配置，不可撤销。选错一个文件等于清档 | 加 `useConfirm()` 二次确认，弹窗里写清将替换什么 |

### 5. 一个值得记下来的坑：Git Bash 会改写 `/` 开头的参数

`node scripts/audit-buttons.mjs --routes=/` 里的 `--routes=/` 被 Git Bash 当成路径，
自动转换成 `--routes=C:/.../PortableGit/versions/1.2.0/`，过滤后一个路由都不剩，
脚本**静默跑完、什么都不验**。`verify-ui.mjs` 的文档里写着同样的用法，也踩同一个坑。

两个脚本都改成：匹配不到任何已知路由就**报错退出**并提示加 `MSYS_NO_PATHCONV=1`。
静默的空跑比报错难查得多。

```bash
node scripts/check-bindings.mjs                          # 27 个文件模板绑定正常
node scripts/verify-ui.mjs                               # 48 组合，0 问题
```

## 第四轮：导出自动分列 + 首页待办区下线

### 1. 导出「按卷子分列」的分组改成完全由卷子名推导

用户拿 `07年真题 / 08年真题 / 09年真题` 的导出截图来问「真题肯定也要分列，能不能自动根据名字来分列」。
先跑了一遍现状（把各种写法喂给 `paperGroupName`），结论是**裸数字尾号能合并，其它写法全漏**：

| 卷子名 | 改动前 | 改动后 |
| --- | --- | --- |
| `09真题` / `11真题` / `12真题` | 各自一列 | **合并成 `真题`** |
| `07年真题` / `08年真题` / `09年真题` | 各自一列 | **合并成 `真题`** |
| `2015 合成成绩` / `2016 合成成绩` | 各自一列 | **合并成 `合成成绩`** |
| `英语一2010` / `英语一2011` | 各自一列 | **合并成 `英语一`** |
| `26张八1` / `26张八2` / `26张八10` | 合并成 `26张八` | 合并成 `张八` |
| `张宇八套卷 第1套` / `第2套` | **不合并** | 合并成 `张宇八套卷` |
| `模拟卷（一）` / `（二）` | **不合并** | 合并成 `模拟卷` |

处理顺序：**剥开头年份 → 剥结尾年份 → 剥结尾序号**（`SEQUENCE_RULES` 三条规则）。

**这里踩过一次方向性错误，记下来**：第一版把「4 位年份不拆」当成必须守住的边界，
还专门加了 `marker.length > 2` 拦截来保护 `英语一2010`。结果用户要的恰恰相反 ——
**年份不该决定分列，年份应该是行**：`09真题 / 11真题 / 12真题` 要并成一整列，
同一列里一年一行才好横向对比。保护年份等于把用户最想要的对比视图拆散了。
现在的取舍是：**年份只影响行顺序，不影响分组**。

剥年份时有两个真会踩到的误伤护栏：

- 4 位年份要求开头是 `19xx` / `20xx`，否则 `1800题` / `1000题` 这类习题册名会被啃掉数字。
- 剥完剩下不足 2 个字就放弃，否则 `2000题` / `50题` 会只剩一个 `题`，
  不同习题册被并到一列。
- 3 位数字（`660题`、`408 综合模拟`）一律不当年份。

**另一条必须守住的边界**：汉字数字不能无脑剥。`英语一` / `数学一` / `数一` 末尾的「一」
是名字本身，不是序号，所以汉字数字规则**要求序号前必须有分隔符或括号**。

回归测试钉在 `scripts/test-paper-group.mjs`：56 条单名断言（既有「必须合并」也有
「必须不合并」）+ 4 组收敛断言 + 6 个端到端 `buildExportMatrix` 场景
（含「不同科目同名不并到一起」「真题和模拟卷不互相并」）。

导出面板的预览说明也补上了规则，用户不用猜名字该怎么写。

### 2. 首页「今日待办」整块下线

首屏那两行（`N 道错题到复习时间了` / `今天已记录 N 条成绩`）和下面的核心指标、
错题库入口说的是同一件事，属于重复播报；用户明确要求去掉。

- 删掉 `todayTasks`、`dueMistakes` 两个 computed 和模板里的 `.ds-task-list`。
- **「该备份了」这条提醒没有跟着一起消失**，挪到了下面的「提醒」模块。
  它是全站唯一的备份提醒，清缓存会丢全部本地数据，不该因为首页减负被删掉。
- `.ds-task` / `.ds-task-list` 的样式保留 —— 「提醒」模块复用同一套结构。
- `todayRecords` / `todayMinutes` 留着，底部脚注的「今天已学习 X」还在用。

首屏现在只剩：问候语 + `记录成绩` / `复习错题` 两个动作 → 筛选 → 核心指标 → 最近成绩。

## 第五轮：导出「每列包含哪些成绩」—— 按列挑行

用户贴了 `阅读`（英一 · 13 条，07阅读…19阅读）的导出截图，要求
「我可以自己选每一栏，比如这个英语我就想要 11 年往后的」。

### 1. 存排除项，不存选中项

`exportForm.matrixExcluded` 存的是**被排除的成绩 id**，不是选中项：

- 新记的成绩默认就在导出里，不会因为以前挑过一次就被悄悄漏掉；
- 用户没挑过任何东西时是空数组，行为和以前完全一致。

排除项按 id 与当前记录集求交集，历史遗留的 id 自然失效，不需要额外的清理逻辑。

### 2. 选择器和预览读两份矩阵（关键设计）

```js
exportMatrixAll  // 没排除任何东西的完整矩阵 —— 只给选择器用
exportMatrix     // 排除之后的矩阵 —— 预览和导出用
```

**必须分成两份**：某一列被「清空」之后，如果选择器读的是过滤后的数据，
那个分组会整个消失，用户就再也点不回来了。选择器读完整矩阵，
分组永远在，清空后还能一键恢复。

### 3. UI

每列一块：组名（用科目色）+ `科目 · 已选 9/13` + `全选` / `清空`，
下面是一排可点的成绩 chip，点一下就把那一年从这列去掉，去掉的 chip
用虚线框 + 删除线表示。顶部有 `全部保留` / `全部去掉` 和「已排除 N 条」。

`已选 x/y` 就放在点的地方，用户不用去看预览也知道自己挑了多少条 ——
选择器有 340px 高度上限并独立滚动，正是为了让下面的预览留在视野里。

### 4. 顺手补上的审计盲区

原来的按钮审计只在**页面初始状态**枚举按钮，而导出面板是点开才出现的 ——
整个面板（列布局、字段、每列选择器）从来没被审到过。这轮把它补上：

- 新增伪路由 `/records · 导出面板`，`click` 打开导出面板再枚举。
- 审计脚本每次点击前清掉导出面板的本地偏好。排除项是持久化的，
  不清的话上一轮点过的「清空」会留到下一轮，后面几次点击落在
  「成绩全被排除」的状态上，判定失真。
- 同时把 `exam-tracker-export-layout` 固定成 `matrix`，
  否则「按卷子分列」才渲染的选择器根本不可见，等于没审。
- `DANGEROUS` 里的 `清空` 收窄成 `清空成绩|清空全部|清空所有`：
  导出面板按列清空只是取消勾选，不是危险操作，原来的正则会把
  它误判成「危险操作没弹确认」。

### 验证

```bash
npm run build
```

## 第六轮：弹窗键盘可达性 + 导出面板抽组件

### 1. 手写弹窗其实关不掉、也关不住焦点

起因是给导出面板写自动检查时顺手量了一下：面板打开后

- 按 `Escape` **关不掉**；
- 连按 12 次 `Tab`，**6 次**焦点跑到了被半透明遮罩盖住的页面按钮上，
  回车就直接点到了看不见的东西。

`role="dialog" aria-modal="true"` 只是给读屏软件的**声明**，浏览器不会
因此限制焦点 —— 之前以为写了这两个属性就完事了，是错的。鼠标用户完全
无感，键盘和读屏用户会直接卡在弹窗里。

新增 `src/composables/useDialogA11y.js` 统一处理五件事：

- 打开后焦点进入弹窗（优先 `[data-autofocus]`）；
- `Tab` / `Shift+Tab` 在弹窗内环绕，焦点跑到外面时拉回来；
- `Escape` 关闭 —— 用 `openStack` 保证只关**最上面**那层；
- 关闭后焦点回到触发它的那个按钮；
- 锁定页面滚动。

五个弹窗全部接入：导出面板、合成成绩、签名、确认框、图片灯箱。
`DsModal.vue` 原来自己手写了一套 Escape + 滚动锁定，也改成复用这个
composable，顺带补上了它一直缺的焦点陷阱。

两个实现细节值得记：

- 判断元素可见**不能用 `offsetParent`** —— `position: fixed` 的子树里
  它恒为 `null`，弹窗本身就是 fixed 的，用了会导致「一个可聚焦元素都找不到」。
  改成 `getClientRects().length > 0` 加 `visibility` 检查。
- 图片灯箱传进去的必须是**布尔**而不是 `activeImage` 本身：翻页时
  `activeImage` 会换成另一个对象，直接传会让 watcher 以为「重新打开了」，
  焦点被反复抢回第一张。

### 2. `scripts/check-dialogs.mjs`：把规则钉死

每个弹窗跑一遍：焦点进入 → 滚动锁定 → `Tab` 14 次不逃逸 →
`Shift+Tab` 不逃逸 → `Escape` 关闭 → 焦点归位 → 滚动恢复。

写这个脚本踩了两个坑，都记在脚本注释里了：

- **滚动锁定必须在第一次打开时就查**。合成成绩那个弹窗会把页面切到
  「合成模式」，关掉之后 `全选当前结果` 这个按钮就不存在了，
  想「再打开一次」是打不开的。
- **别把 Playwright 的错误截成第一行**。`locator.click` 的真正原因
  （找不到 / 被遮挡 / 一直不稳定）全在 `Call log` 里，只留第一行
  就只剩一句没头没脑的 timeout，白白多花半小时。

### 3. 导出面板抽成 `ExportDialog.vue`

`RecordsPage.vue` 原来 2156 行，导出面板占了 400 多行模板加 20 多个
computed，混在成绩列表里既看不清边界，也没法单独验证。

抽出来之后的对外契约只有四个：

```
:model-value            面板开关
:filtered-records       页面当前筛选结果（范围选「当前查询」时用）
:selected-records       页面已勾选的成绩（范围选「已选记录」时用）
:has-active-filters     只影响文案是「当前筛选」还是「当前列表」
```

科目名 / 科目颜色 / 全部成绩 / 提示条都直接从 store 取，不用一层层传。
另外把 `recordTitle`、`recordYear`、`normalizePaperVariant`、
`formatDuration` 等 9 个纯函数抽到 `src/utils/recordDisplay.js` ——
列表和导出预览必须用**同一份**实现，各写一套迟早会对不上。

结果：`RecordsPage.vue` 2156 → 1295 行。

### 4. `scripts/check-export.mjs`：真的把文件导出来拆开看

前面两个脚本都看不出「导出的表到底长什么样」：`audit-buttons` 只能确认
「点了导出有反应」，`check-dialogs` 只能确认「面板能开能关」。而抽组件
最容易错的恰恰是**喂给 Excel 的是哪批成绩** —— 抽错了按钮照样有反应、
预览照样好看，但文件内容是错的。

所以这个脚本直接抓下载的文件，用项目自己的 exceljs 解析，然后断言：

- 灌入 `09真题 / 11真题 / 12真题` 后，第 1 行只出现**一个**「真题」分组标题，
  且不出现任何年份形式的列名；
- 在「每列包含哪些成绩」里点掉 `12真题` 后，文件里**搜不到** `12真题`，
  但 `09真题`、`11真题` 还在；
- demo 记录没丢（说明记录集没被喂错）；
- 列数 = 1（序号）+ 5 套 × 2 字段 = 11。

> 顺带发现：ExcelJS 读回横向合并单元格时，会把主单元格的值复制到合并区
> 的每一个格子上，所以「真题」会连着出现 span 次。相邻分组的 key 一定
> 不同，因此把连续重复的标题折叠掉就是真正的分组列表。

## 第七轮：无障碍与浮层可用性

这一轮先写了一个巡检脚本 `scripts/audit-a11y.mjs` 再动手 —— 不看代码猜，
而是让浏览器把「读屏用户会听到什么、键盘用户能不能操作」算出来。查六件事：
控制台报错、可点元素有没有可访问名称、表单控件有没有 label、图片有没有 alt、
点击目标够不够大、标题层级对不对，外加「系统开了减少动态效果之后还动不动」。

跑第一遍就查出五个真问题。

### 1. 每个页面都有两个 `h1`

顶部条那行（「学习档案 / 成绩」）用的是 `h1`，各页自己的标题（`DsPageHeader`
里的「成绩工作台」）也是 `h1`。读屏用户每进一个页面都会先听到两遍标题。

顶部条那行只是「你现在在哪儿」的位置提示，不是页面标题，所以把它改成 `<p>`。
但这里有个坑：`main.css` / `tablet.css` 里有 **15 条** `.topbar h1` 规则在管
字号、颜色、各断点的响应式。直接换标签会让这些规则**全部失效**，而且不会报错 ——
页面只是悄悄变了个样。

解法是换成 `p.topbar-heading`：`.topbar h1` 的特异度是 (0,1,1)，
`p.topbar-heading` 也是 (0,1,1)，**完全一致**，所以层叠顺序原样保留。
`design-system.css` 里那条覆盖规则也必须跟着写成 `p.topbar-heading`，
降成 `.topbar-heading`（0,1,0）就会被 `main.css` 反过来压住。

改完对比截图：像素完全一致。

顺带把首页那句问候语从 `h2` 提到 `h1` —— 首页本来就没有 `DsPageHeader`，
顶部条不再是标题之后，它会变成唯一一个 `h1`。

### 2. 表单控件没有可访问名称

- 顶部搜索框：一个 `type="search"` 的输入框，没有 label 也没有 placeholder，
  读屏只会念「搜索框」。补上 `aria-label="搜索成绩和错题"`。
- 成绩列表的行选择框：4 个复选框共用同一个 `title="选择为合成来源"`，
  读屏用户根本分不清勾的是哪一条。改成 `aria-label="选择「政治 选择题套卷」作为合成来源"`。
- 两个隐藏的文件框（首页「恢复备份」、备份页「合并导入 / 覆盖恢复」）：
  它们是按钮的实现细节，不该出现在可访问性树里。加 `aria-hidden="true"` + `tabindex="-1"`，
  而不是给它们补 label —— 真正的控件是那两个按钮。

### 3. 浮层点了别处关不掉

全站三个浮层（顶部搜索建议、成绩列表的排序菜单、健康检查的「已忽略」面板）
都只能靠再点一次触发按钮来关。点页面别处，它们会一直挂在那儿挡住内容。

新增 `src/composables/useDismissable.js` 统一处理「点外面 / 按 Escape 就收起」，
三个浮层全部接入。一个必须注意的点写进了注释：

> `containerRef` **必须同时包住触发按钮**。只包浮层的话，点触发按钮会被判成
> 「点在了外面」而先收起，紧接着 click 事件又把它打开 —— 结果就是怎么点都关不掉。

### 4. 系统开了「减少动态效果」，页面照样在动

全站 29 处 `transition`、11 处 `animation`，没有一处理会
`prefers-reduced-motion`。前庭功能敏感的用户在系统里关掉动画之后，
这些位移和缩放照样播，有些人会直接头晕。

在 `design-system.css` 末尾（它最后加载，是最终裁决层）加一条全局规则压住。
时长留 `0.01ms` 而不是 `0s`：有些代码会监听 `transitionend`，设成 0s 那些事件
可能永远不触发，逻辑就卡住了。

### 5. 点击目标

这里踩了自己挖的坑：第一版脚本把「点击目标」量成了那个 16px 的 `input`，
结果报出一堆假问题 —— 真正能被点到的是外面那层 `<label>`。

修正后按 WCAG 2.2 AA 的 **24px** 判定（44px 是 Apple HIG 的建议值，
达不到不算违规，只作为「不够宽裕」列出来参考）。行内文字链接按标准
明确排除，不参与判定。

真正不达标的只有两处：

- 表格里的行选择框：16×16 且**没有** label 包裹。用 `<label>` 包起来并撑到 24×24，
  顺便让整格可点。
- 手机端成绩卡片的选择框：label 是 23×24，差 1px。原因是复选框自带
  `margin: 3px 3px 3px 4px`，`16 + 4 + 3 = 23`。补一条 `min-width: 24px` 解决。

### 6. 顺手清掉的死代码

`DsBadge.vue`、`MetricCard.vue`（各 16 行，全仓零引用）、
`scripts/probe-badge.mjs`（一次性探针，调试对象已经删了）。
`probe-overflow.mjs` 保留 —— 它在 REDESIGN 里有记录，是可复用的溢出定位工具。

### 验证

```bash
npm run build
npm run check          # 绑定 + 分组 + 弹窗键盘 + 导出内容 + 无障碍
npm run check:ui       # 48 个尺寸组合，0 问题
npm run check:buttons  # 120 个按钮，0 报错
```

`audit-a11y` 从「17 类问题」清到「0 类」，并且这六项检查本身也进了
`npm run check`，以后改动不会再悄悄退化。

## 第八轮：store 测试 + 「用时」录入改造

这一轮的两件事都不改外观，改的是「数据对不对」和「愿不愿意填」。

### 1. tracker store 终于有测试了

`src/stores/tracker.js` 1354 行，是全项目最大的文件，此前**零测试**。
里面全是「静默失败」型的逻辑：卷型判错、合成元信息没写进备注、
回收站时间算错 —— 界面上都不报错，只会让数据看起来不对。

真正的障碍是它根本 import 不进 Node：

- 源码写的是 `from "../services/storage"`，**不带扩展名**。Vite 会补 `.js`，
  Node 的 ESM 解析器不会。于是 `Cannot find module '.../services/storage'`。
- 用了 `import.meta.env`，那是 Vite 注入的，Node 里是 `undefined`。

为了测试去改几十个源文件的 import 是本末倒置，所以在**加载阶段**补上：
`scripts/lib/vite-shim.mjs` 提供 `resolve`（只在默认解析失败、且是相对路径
无扩展名时补 `.js`）和 `load`（把 `import.meta.env` 换成 `globalThis.__viteEnv`）
两个钩子。两个钩子都只在「Node 原本会失败」时介入。

**没有引入任何新依赖。** 项目 devDependencies 是空的，所有校验脚本都只用
`node_modules` 里已有的东西 —— 为一个 store 测试破例装 jsdom 会破坏这个约定。
这里需要的浏览器能力少得可怜（`localStorage`、`window` 的定时器、`document.hidden`），
`scripts/lib/browser-env.mjs` 几十行就够了。

IndexedDB 也**不需要**：Dexie 是懒的，不调用写操作就不开库。测试把 `db` 的
表方法换成内存桩 —— 要测的是 store 的逻辑，不是 Dexie 的持久化。

两个坑记一下：

- `navigator` 在 Node 22 里是**只读**全局（`Cannot set property navigator`），
  但其实不用桩：Node 自带的 `navigator.platform` 就是 `"Win32"`，
  `getDeviceName()` 直接能跑。
- `@vue/runtime-dom` 一加载就执行 `doc.createElement("template")`。
  `document` 存在但没有 `createElement` 会直接 TypeError，所以桩里必须有这个方法
  （返回一个不会被真正使用的空壳节点）。这个桩只服务于「import store 并调它的逻辑」，
  真要渲染组件还是得上 jsdom。

覆盖 72 项断言：成绩归一化（分数/用时/记录类型）、卷型判定（**只有数一**才分真题模拟）、
习题记录名拼接、合成成绩的元信息往返与非法输入拦截、回收站 24 小时 TTL、科目名兜底、
以及写入是否真的落到存储层。

**验证测试本身有效**：往 `tracker.js` 注入三处改动（用时不再四舍五入、卷型不再限制在
数一、回收站 TTL 从 24h 改成 12h），5 条断言立刻失败；还原后回到 72/0。
不会失败的测试等于没有测试。

### 2.「用时」为什么没人填

假设是录入太麻烦。静态看代码就印证了：

```html
<!-- 改前 -->
<label>用时（分钟）<input type="number" min="0" step="1" /></label>
```

但**全站都把这个值显示成「1 小时 30 分钟」** —— 仪表盘、记录详情、导出、
热力图，四处都是。也就是同一件事在界面上有两套单位：**看到的是小时，要填的是分钟**。
每录一条都要在脑子里换算一次，而这个字段又是选填的，换算的麻烦就直接变成了
「算了不填」。

改成「小时 + 分钟」两个框，再配一排常用时长的快捷按钮（45 分 / 1 时 / 1.5 时 /
2 时 / 2.5 时 / 3 时，覆盖考研常见时长，一次点击搞定）。

几个细节：

- **存储格式一个字没改**，仍然是 `durationMinutes` 的整数分钟。所以 store、导出、
  统计口径、所有读这个字段的地方都不用动。
- 分钟框填 90 会**自动进位**成 1 小时 30 分，而不是被截成 30。
- 再点一次已选中的预设就取消，不用手动清空两个框。
- 预设的高亮跟着**合成后的值**走：手动填 1 小时 30 分，「1.5 时」也会亮起来。
- 空值和 0 严格区分：两个框都空 → `""`（未记录），明确填 0 → `0`。
  store 里 `hasDuration()` 是按 `!== ""` 判定的，把空值落成 0 会让
  「未记录用时」的健康检查漏报。

**顺手合并了四份重复实现。** `formatDuration` 原本有三个文件各写了一份
（`DashboardPage`、`RecordDetailPage`、`ContributionHeatmap`），
和 `utils/recordDisplay.js` 里已有的那份几乎一样，只有空态文案不同。
现在统一到 `recordDisplay.js`，空态文案做成参数。同一个数据在不同页面上
显示成不同样子，是这类 bug 里最难排查的一种。

新逻辑配了 `scripts/test-duration.mjs`（44 项断言）。最要紧的一条是
**split → compose 的往返**：拆成两个输入框再合回去，必须还是原来的数。
不成立的话，用户打开编辑弹窗、什么都不改、直接保存，数据就悄悄变了。
对 17 个取值逐一验证。

### 3. 把「填得少」变成能判断的数字

健康检查里原来只说「有几条没记用时」。数字本身说明不了要不要管 ——
补上占比：「占全部成绩的 34%」。这样才分得清「偶有遗漏」和「一半都没记」。

### 4. 审计脚本自己的两个问题

- **`audit-a11y` 漏审了最主要的录入界面。** 录入表单在首页是收起的，
  要先点「记录成绩」才展开，而它只扫初始状态 —— 于是全站最主要的数据入口
  从来没被审过。给它加了 `prepare()` 步骤，同时 `audit-buttons` 也补上了
  对应的路由（按钮总数 120 → 131）。
- **`--only` 匹配不到时静默跑 0 个路由还报「全部通过」。** Git Bash 会把
  `/` 开头的参数当路径转换（`--only=/` → `--only=C:/.../PortableGit/...`），
  一个都匹配不上，脚本却照样打印 ✓。改成匹配不到就报错退出。
  `verify-ui.mjs` 早就有这个防护，`audit-a11y` 漏了。

新增的「用时」控件也过了审计：两个输入框各有 `aria-label`，
预设按钮在窄屏折成两行后每行只有 19.6px，补了 `min-height: 26px`
（分段控件里按钮紧挨着，拿不到 WCAG 2.5.8 的间距豁免）。
