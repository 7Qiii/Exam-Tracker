### 1.3 数据模型（不可破坏）

```
subject   { id, name, fullScore, color, hidden, sortOrder }
record    { id, subjectId, paperName, recordType: paper|exercise|composite,
            paperVariant: true|mock, score, fullScore, date, durationMinutes,
            exerciseBookName, exercisePage, exerciseQuestion,
            note, pendingSync, createdAt, ... }
mistake   { id, subjectId, title, knowledgePoint, analysis, status, difficulty,
            sourceRecordId, questionText, nextReviewAt, reviewedAt,
            createdAt, updatedAt }
image     { id, ownerType, ownerId, name, size, storageKey, url, pendingUpload, uploadError }
```

错题状态枚举：`待复盘 / 不熟 / 不会 / 已整理 / 已掌握`；难度：`简单 / 中等 / 困难`。

### 1.4 现状问题

1. **样式层失控**：`main.css` 7682 行里叠了 4 套以上主题层，反复覆盖同一批选择器，改一处要靠 `!important` 抢优先级。
2. **信息架构平铺**：侧栏 6 个入口无分组，「同步」和「备份」与业务页同级，缺少「复盘」这一条主线。
3. **首页堆砌**：统计数字 + 焦点 + 提醒 + 快捷入口 + 2 个图表，模块之间没有主次，缺少「一眼看到进度」的核心面板。
4. **移动端入口过多**：底部导航塞了 6 项，拥挤。
5. **状态缺失**：加载态只有一句「正在加载本地学习档案...」，没有 skeleton；错误态基本没有；删除用 `window.confirm`。
6. **反馈不统一**：有的用 inline alert，有的用 Toast，有的什么都不给。

掌握状态用色：`已掌握 = green`、`已整理 = blue`、`不熟 = orange`、`不会 = red`、`待复盘 = muted`。

### 4.2 圆角 / 阴影 / 间距

- 圆角：`--r-sm 6px`、`--r-md 10px`、`--r-lg 14px`、`--r-pill 999px`。卡片用 `md`，弹窗用 `lg`，**不做大圆角**。
- 阴影：`--shadow-xs`（卡片默认）、`--shadow-sm`（hover）、`--shadow-md`（弹窗）。均为低透明度单层投影。
- 间距刻度：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40`。
- 栅格：桌面 12 列（`gap 16px`），内容最大宽度 `1200px`；平板 8 列；移动 4 列。

### 4.3 字号与字重

| 用途 | 字号 | 字重 |
| --- | --- | --- |
| 页面标题 | 22px | 700 |
| 模块标题 | 15px | 600 |
| 指标数值 | 26px | 700 |
| 正文 | 14px | 400 |
| 辅助说明 | 12px | 400 |
| 标签 | 12px | 600 |

### 4.4 断点

沿用现有约定，不再新增：

- `≤ 460px` 小屏手机
- `≤ 767px` 手机
- `768 – 1023px` 平板竖屏
- `1024 – 1180px` 平板横屏
- `≥ 1181px` 桌面

### 4.5 组件规范

统一由 `design-system.css` 定义：按钮（primary / secondary / ghost / danger，四态齐全）、输入框（默认/聚焦/错误/禁用）、下拉、标签、进度条、表格、卡片、弹窗、Toast、骨架屏、空状态。

### 首页（DashboardPage）

按八块重构：欢迎区（问候语随时段变化）→ 今日待办（到期错题 / 今日是否已记录 / 备份时效，全部由真实数据推导）→ 顶部筛选（科目 + 时间范围，作用于整页并写入 localStorage）→ 核心指标 → 快速录入 → 科目掌握度（练习进度 / 平均分 / 得分率 / 错题数 + 五态分布条）→ 学习贡献热力图 + 提醒 + 快捷入口 → 分数趋势 → 最近成绩。

明确没有做的事：没有编造「今日目标」，没有做收藏功能——这些在现有数据里没有依据，宁可空着也不塞假数据。

### 热力图（ContributionHeatmap）

- 原生 `title` 换成自绘 tooltip（桌面 hover）+ 常驻读数行（触屏点按），因为 `title` 在 iPad 上根本弹不出来。
- 每天统计成绩条数、错题条数、成绩里记录的用时；没记用时就是「未记录用时」，不猜。
- 加了月份刻度；移动端横向滚动并在挂载后自动滚到最右（最近的日子）。

### 成绩图表（ScoreCharts）

- 支持时间范围筛选（`rangeDays`，0 = 全部）。
- 颜色从设计 token 读取，不再散落硬编码色值。
- 两个面板各自独立初始化：某个面板没数据被 `v-if` 掉时，另一个照常渲染，且容器消失时会销毁对应实例。
- 用 `ResizeObserver` 适配侧栏在「图标条 / 抽屉」之间切换导致的宽度变化。

### 错题连续复习

- 列表页：状态 chip（带各状态数量，点一下即筛选）、搜索 / 科目 / 章节（复用 `knowledgePoint`）/ 难度 / 排序全部即时生效，筛选条件写入 URL query。
- 详情页：上一题 / 下一题沿用列表页的筛选与排序（条件通过 query 带过去），所以「筛出 5 道不熟的题」就能顺着这 5 道翻完；状态可就地切换；桌面端支持 `←` `→` 翻题、`1`–`5` 切状态。
- 复习日志只写 localStorage，不改动 IndexedDB 里的错题结构。

### 交互与表单

- 6 处 `window.confirm` 全部替换为站内确认弹窗（`useConfirm()`），删除后的成功提示沿用 store 里已有的 toast。
- 成绩页筛选改为即时生效：下拉一改就应用，关键词输入 260ms 防抖。同步筛选时不再顺手收起录入面板，避免打断正在填的表单。
- 桌面端顶栏吸顶；底部标签栏从 6 项精简为 5 项（总览 / 成绩 / 错题 / 科目 / 备份），同步入口保留在顶栏账号区。
- 侧栏导航按「学习 / 管理」分组；详情页里侧栏选中态自己判定（路由是扁平注册的，`router-link-active` 不会把 `/records` 认成 `/records/123` 的父级）。

### 2. `scripts/prune-css.mjs`：安全剪掉死样式

上面这轮替换让 `records-hero`、`records-metric`、`summary-grid`、`detail-head`、`detail-copy`、`subject-detail-panel` 等一批类彻底失去引用。
直接手删 7800 行的 CSS 风险太高，所以写了个剪枝器：

- **不做自动推断**。模板里存在 `preview-cell-${fieldId}`、`is-${tone}`、`tone-${tone}` 这类拼接类名，
  「CSS 里定义了但 .vue 里搜不到」并不等于死类，自动推断一定会误删。死类清单必须显式给出。
- 选择器列表按顶层逗号拆开，**只摘掉命中死类的那些选择器**；只要还剩一个活的，规则就保留。
- 递归进入 `@media / @supports / @layer / @container`，块内全空才整块丢。
- 扫描时跳过注释与字符串，规则前的注释单独留存，不会因为规则被删而丢掉章节分隔说明。

结果：`main.css` 7839 → 7631 行、`design-system.css` 2946 → 2916 行，共丢 39 条规则、摘除 130 个选择器，
CSS 产物 162.4 kB → 157.5 kB。

验证方式不是「看着没问题」，而是**拿剪枝前的 49 张截图做哈希比对**：
剪枝前后 10 张有差异，但同一份代码连跑两次也有 6~8 张差异，且差异全部集中在带列表的错题页——
逐张看过，布局、间距、颜色、字号完全一致，只是列表首条卡片不同（数据顺序），所以判定为非回归。

### 3. 顺手修掉错题排序的不确定性

`filterAndSortMistakes` 的四个比较函数都没有兜底键。`createdAt` 相同时（批量导入、同一天连续录入很常见）

## 第三轮：首页减负 + 导出入口 + 按钮实测

用户反馈三件事：首页太长、「科目掌握度」那四张卡很突兀、找不到导出按钮，另外怀疑有按钮是摆设。

### 1. 首页从 10 块压到 6 块常驻

| 改前 | 改后 |
| --- | --- |
| 欢迎区、今日待办分成两块 | 合并为一个 `.ds-welcome-block` |
| 科目掌握度（四张科目卡 + 五态分布条） | **整块移到 `/subjects`**，改名「掌握概览」 |
| 学习贡献热力图（屏高很大） | 默认折叠，点标题展开，展开状态存 localStorage |

| 最近成绩 6 条 | 8 条 |

常驻区块：欢迎区（含待办）→ 筛选 → 指标卡 → 最近成绩 → 分数趋势 → 提醒 + 快捷入口。

`<div role="button" tabindex="0">` + Enter/Space 键盘支持，没有硬塞成 button。

### 2. 导出按钮的可发现性

导出成绩（Excel）本来只存在于成绩页顶部，而首页「快捷入口」里放的是「导出 JSON」——
那是整站备份，跟成绩导出不是一回事，名字却很像，所以用户找不到。

- 首页快捷入口新增「导出成绩 Excel」，直接调 `exportRecordsToExcel` 导出全部成绩（一步到位，
  不弹配置面板；要挑字段、按卷子分列仍去成绩页的导出面板）。
- 原有两个入口改名：`导出 JSON` → **备份全部数据**、`合并导入` → **恢复备份**。

### 3. `scripts/audit-buttons.mjs`：把每个按钮真的点一遍

静态扫过：全站 138 个 `<button>` 都绑了事件，也没有「敬请期待 / 开发中」这类占位文案，
所以「摆设 UI」的怀疑不成立。真正会出问题的是**点了没反应 / 点了报错 / 点了把界面搞坏**，
这个只能真点。脚本要点：

- 每点一个按钮前**重新加载页面**：状态天然干净，不用写复原逻辑；危险操作即使弹出了确认框，
  重载也会丢弃，不会真的删数据。
- 点击前后各取一次签名（路由、文字哈希、弹窗数、Toast 数、可见按钮数、主题属性），
  用来判断「到底有没有发生什么」。**主题属性必须带上**，否则「跟随系统/浅色/深色」
  只改属性不改文字，会被误判成无反应。
- 按钮选择器是 `button, [role="button"]`——折叠开关是 role=button 的 div，只扫 `<button>` 会漏。
- 文件类按钮（合并导入 / 恢复备份 / 覆盖恢复）会拉起系统选择框，DOM 上没有任何变化。
  用 Playwright 的 `filechooser` 事件喂一个**结构合法但内容为空**的备份：JSON.parse 能过，
  确认框会正常弹出，路径被真正走到；内容为空且脚本永不点「确认」，所以不会改到测试数据。

**实测结果：72 个按钮，0 报错，没有危险操作漏掉确认。**
5 个「无可见变化」逐个核对过，都是合理无反馈：状态 chip 点的是当前已选状态、
错题状态按钮点的是当前已是该状态、科目名称为空时提交被表单校验挡下、登录页分段控件点的是当前模式。

### 4. 顺手修掉的两个真 bug

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 错题详情「完成本次复习」在题目已是「已掌握」时**完全没反应** | `markReviewed` 直接调 `setStatus("已掌握")`，而 `setStatus` 遇到状态未变会 `return`。于是「已掌握的题再复习一遍」——间隔重复里最常见的场景——不计复习次数、不更新复习时间、连 toast 都没有 | 改成无论状态是否变化都记一次复习，并按情况给不同文案 |
| 备份页「覆盖恢复」**没有任何二次确认** | `onImport` 解析完文件直接 `importData(payload, false)`，而覆盖恢复会清掉全部成绩、错题、图片和科目配置，不可撤销。选错一个文件等于清档 | 加 `useConfirm()` 二次确认，弹窗里写清将替换什么 |

### 5. 一个值得记下来的坑：Git Bash 会改写 `/` 开头的参数

`node scripts/audit-buttons.mjs --routes=/` 里的 `--routes=/` 被 Git Bash 当成路径，
自动转换成 `--routes=C:/.../PortableGit/versions/1.2.0/`，过滤后一个路由都不剩，
脚本**静默跑完、什么都不验**。`verify-ui.mjs` 的文档里写着同样的用法，也踩同一个坑。

两个脚本都改成：匹配不到任何已知路由就**报错退出**并提示加 `MSYS_NO_PATHCONV=1`。
静默的空跑比报错难查得多。

```bash
node scripts/check-bindings.mjs                          # 27 个文件模板绑定正常
node scripts/verify-ui.mjs                               # 48 组合，0 问题
```

## 第四轮：导出自动分列 + 首页待办区下线

### 1. 导出「按卷子分列」的分组改成完全由卷子名推导

用户拿 `07年真题 / 08年真题 / 09年真题` 的导出截图来问「真题肯定也要分列，能不能自动根据名字来分列」。
先跑了一遍现状（把各种写法喂给 `paperGroupName`），结论是**裸数字尾号能合并，其它写法全漏**：

| 卷子名 | 改动前 | 改动后 |
| --- | --- | --- |
| `09真题` / `11真题` / `12真题` | 各自一列 | **合并成 `真题`** |
| `07年真题` / `08年真题` / `09年真题` | 各自一列 | **合并成 `真题`** |
| `2015 合成成绩` / `2016 合成成绩` | 各自一列 | **合并成 `合成成绩`** |
| `英语一2010` / `英语一2011` | 各自一列 | **合并成 `英语一`** |
| `26张八1` / `26张八2` / `26张八10` | 合并成 `26张八` | 合并成 `张八` |
| `张宇八套卷 第1套` / `第2套` | **不合并** | 合并成 `张宇八套卷` |
| `模拟卷（一）` / `（二）` | **不合并** | 合并成 `模拟卷` |

处理顺序：**剥开头年份 → 剥结尾年份 → 剥结尾序号**（`SEQUENCE_RULES` 三条规则）。

**这里踩过一次方向性错误，记下来**：第一版把「4 位年份不拆」当成必须守住的边界，
还专门加了 `marker.length > 2` 拦截来保护 `英语一2010`。结果用户要的恰恰相反 ——
**年份不该决定分列，年份应该是行**：`09真题 / 11真题 / 12真题` 要并成一整列，
同一列里一年一行才好横向对比。保护年份等于把用户最想要的对比视图拆散了。
现在的取舍是：**年份只影响行顺序，不影响分组**。

剥年份时有两个真会踩到的误伤护栏：

- 4 位年份要求开头是 `19xx` / `20xx`，否则 `1800题` / `1000题` 这类习题册名会被啃掉数字。
- 剥完剩下不足 2 个字就放弃，否则 `2000题` / `50题` 会只剩一个 `题`，
  不同习题册被并到一列。
- 3 位数字（`660题`、`408 综合模拟`）一律不当年份。

**另一条必须守住的边界**：汉字数字不能无脑剥。`英语一` / `数学一` / `数一` 末尾的「一」
是名字本身，不是序号，所以汉字数字规则**要求序号前必须有分隔符或括号**。

回归测试钉在 `scripts/test-paper-group.mjs`：56 条单名断言（既有「必须合并」也有
「必须不合并」）+ 4 组收敛断言 + 6 个端到端 `buildExportMatrix` 场景
（含「不同科目同名不并到一起」「真题和模拟卷不互相并」）。

导出面板的预览说明也补上了规则，用户不用猜名字该怎么写。

### 2. 首页「今日待办」整块下线

首屏那两行（`N 道错题到复习时间了` / `今天已记录 N 条成绩`）和下面的核心指标、
错题库入口说的是同一件事，属于重复播报；用户明确要求去掉。

- 删掉 `todayTasks`、`dueMistakes` 两个 computed 和模板里的 `.ds-task-list`。
- **「该备份了」这条提醒没有跟着一起消失**，挪到了下面的「提醒」模块。
  它是全站唯一的备份提醒，清缓存会丢全部本地数据，不该因为首页减负被删掉。
- `.ds-task` / `.ds-task-list` 的样式保留 —— 「提醒」模块复用同一套结构。
- `todayRecords` / `todayMinutes` 留着，底部脚注的「今天已学习 X」还在用。

首屏现在只剩：问候语 + `记录成绩` / `复习错题` 两个动作 → 筛选 → 核心指标 → 最近成绩。

## 第五轮：导出「每列包含哪些成绩」—— 按列挑行

用户贴了 `阅读`（英一 · 13 条，07阅读…19阅读）的导出截图，要求
「我可以自己选每一栏，比如这个英语我就想要 11 年往后的」。

### 1. 存排除项，不存选中项

`exportForm.matrixExcluded` 存的是**被排除的成绩 id**，不是选中项：

- 新记的成绩默认就在导出里，不会因为以前挑过一次就被悄悄漏掉；
- 用户没挑过任何东西时是空数组，行为和以前完全一致。

排除项按 id 与当前记录集求交集，历史遗留的 id 自然失效，不需要额外的清理逻辑。

### 2. 选择器和预览读两份矩阵（关键设计）

```js
exportMatrixAll  // 没排除任何东西的完整矩阵 —— 只给选择器用
exportMatrix     // 排除之后的矩阵 —— 预览和导出用
```

**必须分成两份**：某一列被「清空」之后，如果选择器读的是过滤后的数据，
那个分组会整个消失，用户就再也点不回来了。选择器读完整矩阵，
分组永远在，清空后还能一键恢复。

### 3. UI

每列一块：组名（用科目色）+ `科目 · 已选 9/13` + `全选` / `清空`，
下面是一排可点的成绩 chip，点一下就把那一年从这列去掉，去掉的 chip
用虚线框 + 删除线表示。顶部有 `全部保留` / `全部去掉` 和「已排除 N 条」。

`已选 x/y` 就放在点的地方，用户不用去看预览也知道自己挑了多少条 ——
选择器有 340px 高度上限并独立滚动，正是为了让下面的预览留在视野里。

### 4. 顺手补上的审计盲区

原来的按钮审计只在**页面初始状态**枚举按钮，而导出面板是点开才出现的 ——
整个面板（列布局、字段、每列选择器）从来没被审到过。这轮把它补上：

- 新增伪路由 `/records · 导出面板`，`click` 打开导出面板再枚举。
- 审计脚本每次点击前清掉导出面板的本地偏好。排除项是持久化的，
  不清的话上一轮点过的「清空」会留到下一轮，后面几次点击落在
  「成绩全被排除」的状态上，判定失真。
- 同时把 `exam-tracker-export-layout` 固定成 `matrix`，
  否则「按卷子分列」才渲染的选择器根本不可见，等于没审。
- `DANGEROUS` 里的 `清空` 收窄成 `清空成绩|清空全部|清空所有`：
  导出面板按列清空只是取消勾选，不是危险操作，原来的正则会把
  它误判成「危险操作没弹确认」。

### 验证

```bash
npm run build
node scripts/test-paper-group.mjs                        # 全通过
node scripts/verify-ui.mjs                               # 48 组合，0 问题
```

## 第六轮：弹窗键盘可达性 + 导出面板抽组件

### 1. 手写弹窗其实关不掉、也关不住焦点

起因是给导出面板写自动检查时顺手量了一下：面板打开后

- 按 `Escape` **关不掉**；
- 连按 12 次 `Tab`，**6 次**焦点跑到了被半透明遮罩盖住的页面按钮上，
  回车就直接点到了看不见的东西。

`role="dialog" aria-modal="true"` 只是给读屏软件的**声明**，浏览器不会
因此限制焦点 —— 之前以为写了这两个属性就完事了，是错的。鼠标用户完全
无感，键盘和读屏用户会直接卡在弹窗里。

新增 `src/composables/useDialogA11y.js` 统一处理五件事：

- 打开后焦点进入弹窗（优先 `[data-autofocus]`）；
- `Tab` / `Shift+Tab` 在弹窗内环绕，焦点跑到外面时拉回来；
- `Escape` 关闭 —— 用 `openStack` 保证只关**最上面**那层；
- 关闭后焦点回到触发它的那个按钮；
- 锁定页面滚动。

五个弹窗全部接入：导出面板、合成成绩、签名、确认框、图片灯箱。
`DsModal.vue` 原来自己手写了一套 Escape + 滚动锁定，也改成复用这个
composable，顺带补上了它一直缺的焦点陷阱。

两个实现细节值得记：

- 判断元素可见**不能用 `offsetParent`** —— `position: fixed` 的子树里
  它恒为 `null`，弹窗本身就是 fixed 的，用了会导致「一个可聚焦元素都找不到」。
  改成 `getClientRects().length > 0` 加 `visibility` 检查。
- 图片灯箱传进去的必须是**布尔**而不是 `activeImage` 本身：翻页时
  `activeImage` 会换成另一个对象，直接传会让 watcher 以为「重新打开了」，
  焦点被反复抢回第一张。

### 2. `scripts/check-dialogs.mjs`：把规则钉死

每个弹窗跑一遍：焦点进入 → 滚动锁定 → `Tab` 14 次不逃逸 →
`Shift+Tab` 不逃逸 → `Escape` 关闭 → 焦点归位 → 滚动恢复。

写这个脚本踩了两个坑，都记在脚本注释里了：

- **滚动锁定必须在第一次打开时就查**。合成成绩那个弹窗会把页面切到
  「合成模式」，关掉之后 `全选当前结果` 这个按钮就不存在了，
  想「再打开一次」是打不开的。
- **别把 Playwright 的错误截成第一行**。`locator.click` 的真正原因
  （找不到 / 被遮挡 / 一直不稳定）全在 `Call log` 里，只留第一行
  就只剩一句没头没脑的 timeout，白白多花半小时。

### 3. 导出面板抽成 `ExportDialog.vue`

`RecordsPage.vue` 原来 2156 行，导出面板占了 400 多行模板加 20 多个
computed，混在成绩列表里既看不清边界，也没法单独验证。

抽出来之后的对外契约只有四个：

```
:model-value            面板开关
:filtered-records       页面当前筛选结果（范围选「当前查询」时用）
:selected-records       页面已勾选的成绩（范围选「已选记录」时用）
:has-active-filters     只影响文案是「当前筛选」还是「当前列表」
```

科目名 / 科目颜色 / 全部成绩 / 提示条都直接从 store 取，不用一层层传。
另外把 `recordTitle`、`recordYear`、`normalizePaperVariant`、
`formatDuration` 等 9 个纯函数抽到 `src/utils/recordDisplay.js` ——
列表和导出预览必须用**同一份**实现，各写一套迟早会对不上。

结果：`RecordsPage.vue` 2156 → 1295 行。

### 4. `scripts/check-export.mjs`：真的把文件导出来拆开看

前面两个脚本都看不出「导出的表到底长什么样」：`audit-buttons` 只能确认
「点了导出有反应」，`check-dialogs` 只能确认「面板能开能关」。而抽组件
最容易错的恰恰是**喂给 Excel 的是哪批成绩** —— 抽错了按钮照样有反应、
预览照样好看，但文件内容是错的。

所以这个脚本直接抓下载的文件，用项目自己的 exceljs 解析，然后断言：

- 灌入 `09真题 / 11真题 / 12真题` 后，第 1 行只出现**一个**「真题」分组标题，
  且不出现任何年份形式的列名；
- 在「每列包含哪些成绩」里点掉 `12真题` 后，文件里**搜不到** `12真题`，
  但 `09真题`、`11真题` 还在；
- demo 记录没丢（说明记录集没被喂错）；
- 列数 = 1（序号）+ 5 套 × 2 字段 = 11。

> 顺带发现：ExcelJS 读回横向合并单元格时，会把主单元格的值复制到合并区
> 的每一个格子上，所以「真题」会连着出现 span 次。相邻分组的 key 一定
> 不同，因此把连续重复的标题折叠掉就是真正的分组列表。

## 第七轮：无障碍与浮层可用性

这一轮先写了一个巡检脚本 `scripts/audit-a11y.mjs` 再动手 —— 不看代码猜，
而是让浏览器把「读屏用户会听到什么、键盘用户能不能操作」算出来。查六件事：
控制台报错、可点元素有没有可访问名称、表单控件有没有 label、图片有没有 alt、
点击目标够不够大、标题层级对不对，外加「系统开了减少动态效果之后还动不动」。

跑第一遍就查出五个真问题。

### 1. 每个页面都有两个 `h1`

顶部条那行（「学习档案 / 成绩」）用的是 `h1`，各页自己的标题（`DsPageHeader`
里的「成绩工作台」）也是 `h1`。读屏用户每进一个页面都会先听到两遍标题。

顶部条那行只是「你现在在哪儿」的位置提示，不是页面标题，所以把它改成 `<p>`。
但这里有个坑：`main.css` / `tablet.css` 里有 **15 条** `.topbar h1` 规则在管
字号、颜色、各断点的响应式。直接换标签会让这些规则**全部失效**，而且不会报错 ——
页面只是悄悄变了个样。

解法是换成 `p.topbar-heading`：`.topbar h1` 的特异度是 (0,1,1)，
`p.topbar-heading` 也是 (0,1,1)，**完全一致**，所以层叠顺序原样保留。
`design-system.css` 里那条覆盖规则也必须跟着写成 `p.topbar-heading`，
降成 `.topbar-heading`（0,1,0）就会被 `main.css` 反过来压住。

改完对比截图：像素完全一致。

顺带把首页那句问候语从 `h2` 提到 `h1` —— 首页本来就没有 `DsPageHeader`，
顶部条不再是标题之后，它会变成唯一一个 `h1`。

### 2. 表单控件没有可访问名称

- 顶部搜索框：一个 `type="search"` 的输入框，没有 label 也没有 placeholder，
  读屏只会念「搜索框」。补上 `aria-label="搜索成绩和错题"`。
- 成绩列表的行选择框：4 个复选框共用同一个 `title="选择为合成来源"`，
  读屏用户根本分不清勾的是哪一条。改成 `aria-label="选择「政治 选择题套卷」作为合成来源"`。
- 两个隐藏的文件框（首页「恢复备份」、备份页「合并导入 / 覆盖恢复」）：
  它们是按钮的实现细节，不该出现在可访问性树里。加 `aria-hidden="true"` + `tabindex="-1"`，
  而不是给它们补 label —— 真正的控件是那两个按钮。

### 3. 浮层点了别处关不掉

全站三个浮层（顶部搜索建议、成绩列表的排序菜单、健康检查的「已忽略」面板）
都只能靠再点一次触发按钮来关。点页面别处，它们会一直挂在那儿挡住内容。

新增 `src/composables/useDismissable.js` 统一处理「点外面 / 按 Escape 就收起」，
三个浮层全部接入。一个必须注意的点写进了注释：

> `containerRef` **必须同时包住触发按钮**。只包浮层的话，点触发按钮会被判成
> 「点在了外面」而先收起，紧接着 click 事件又把它打开 —— 结果就是怎么点都关不掉。

### 4. 系统开了「减少动态效果」，页面照样在动

全站 29 处 `transition`、11 处 `animation`，没有一处理会
`prefers-reduced-motion`。前庭功能敏感的用户在系统里关掉动画之后，
这些位移和缩放照样播，有些人会直接头晕。

在 `design-system.css` 末尾（它最后加载，是最终裁决层）加一条全局规则压住。
时长留 `0.01ms` 而不是 `0s`：有些代码会监听 `transitionend`，设成 0s 那些事件
可能永远不触发，逻辑就卡住了。

### 5. 点击目标

这里踩了自己挖的坑：第一版脚本把「点击目标」量成了那个 16px 的 `input`，
结果报出一堆假问题 —— 真正能被点到的是外面那层 `<label>`。

修正后按 WCAG 2.2 AA 的 **24px** 判定（44px 是 Apple HIG 的建议值，
达不到不算违规，只作为「不够宽裕」列出来参考）。行内文字链接按标准
明确排除，不参与判定。

真正不达标的只有两处：

- 表格里的行选择框：16×16 且**没有** label 包裹。用 `<label>` 包起来并撑到 24×24，
  顺便让整格可点。
- 手机端成绩卡片的选择框：label 是 23×24，差 1px。原因是复选框自带
  `margin: 3px 3px 3px 4px`，`16 + 4 + 3 = 23`。补一条 `min-width: 24px` 解决。

### 6. 顺手清掉的死代码

`DsBadge.vue`、`MetricCard.vue`（各 16 行，全仓零引用）、
`scripts/probe-badge.mjs`（一次性探针，调试对象已经删了）。
`probe-overflow.mjs` 保留 —— 它在 REDESIGN 里有记录，是可复用的溢出定位工具。

### 验证

```bash
npm run build
npm run check          # 绑定 + 分组 + 弹窗键盘 + 导出内容 + 无障碍
npm run check:ui       # 48 个尺寸组合，0 问题
npm run check:buttons  # 120 个按钮，0 报错
```

`audit-a11y` 从「17 类问题」清到「0 类」，并且这六项检查本身也进了
`npm run check`，以后改动不会再悄悄退化。

## 第八轮：store 测试 + 「用时」录入改造

这一轮的两件事都不改外观，改的是「数据对不对」和「愿不愿意填」。

### 1. tracker store 终于有测试了

`src/stores/tracker.js` 1354 行，是全项目最大的文件，此前**零测试**。
里面全是「静默失败」型的逻辑：卷型判错、合成元信息没写进备注、
回收站时间算错 —— 界面上都不报错，只会让数据看起来不对。

真正的障碍是它根本 import 不进 Node：

- 源码写的是 `from "../services/storage"`，**不带扩展名**。Vite 会补 `.js`，
  Node 的 ESM 解析器不会。于是 `Cannot find module '.../services/storage'`。
- 用了 `import.meta.env`，那是 Vite 注入的，Node 里是 `undefined`。

为了测试去改几十个源文件的 import 是本末倒置，所以在**加载阶段**补上：
`scripts/lib/vite-shim.mjs` 提供 `resolve`（只在默认解析失败、且是相对路径
无扩展名时补 `.js`）和 `load`（把 `import.meta.env` 换成 `globalThis.__viteEnv`）
两个钩子。两个钩子都只在「Node 原本会失败」时介入。

**没有引入任何新依赖。** 项目 devDependencies 是空的，所有校验脚本都只用
`node_modules` 里已有的东西 —— 为一个 store 测试破例装 jsdom 会破坏这个约定。
这里需要的浏览器能力少得可怜（`localStorage`、`window` 的定时器、`document.hidden`），
`scripts/lib/browser-env.mjs` 几十行就够了。

IndexedDB 也**不需要**：Dexie 是懒的，不调用写操作就不开库。测试把 `db` 的
表方法换成内存桩 —— 要测的是 store 的逻辑，不是 Dexie 的持久化。

两个坑记一下：

- `navigator` 在 Node 22 里是**只读**全局（`Cannot set property navigator`），
  但其实不用桩：Node 自带的 `navigator.platform` 就是 `"Win32"`，
  `getDeviceName()` 直接能跑。
- `@vue/runtime-dom` 一加载就执行 `doc.createElement("template")`。
  `document` 存在但没有 `createElement` 会直接 TypeError，所以桩里必须有这个方法
  （返回一个不会被真正使用的空壳节点）。这个桩只服务于「import store 并调它的逻辑」，
  真要渲染组件还是得上 jsdom。

覆盖 72 项断言：成绩归一化（分数/用时/记录类型）、卷型判定（**只有数一**才分真题模拟）、
习题记录名拼接、合成成绩的元信息往返与非法输入拦截、回收站 24 小时 TTL、科目名兜底、
以及写入是否真的落到存储层。

**验证测试本身有效**：往 `tracker.js` 注入三处改动（用时不再四舍五入、卷型不再限制在
数一、回收站 TTL 从 24h 改成 12h），5 条断言立刻失败；还原后回到 72/0。
不会失败的测试等于没有测试。

### 2.「用时」为什么没人填

假设是录入太麻烦。静态看代码就印证了：

```html
<!-- 改前 -->
<label>用时（分钟）<input type="number" min="0" step="1" /></label>
```

但**全站都把这个值显示成「1 小时 30 分钟」** —— 仪表盘、记录详情、导出、
热力图，四处都是。也就是同一件事在界面上有两套单位：**看到的是小时，要填的是分钟**。
每录一条都要在脑子里换算一次，而这个字段又是选填的，换算的麻烦就直接变成了
「算了不填」。

改成「小时 + 分钟」两个框，再配一排常用时长的快捷按钮（45 分 / 1 时 / 1.5 时 /
2 时 / 2.5 时 / 3 时，覆盖考研常见时长，一次点击搞定）。

几个细节：

- **存储格式一个字没改**，仍然是 `durationMinutes` 的整数分钟。所以 store、导出、
  统计口径、所有读这个字段的地方都不用动。
- 分钟框填 90 会**自动进位**成 1 小时 30 分，而不是被截成 30。
- 再点一次已选中的预设就取消，不用手动清空两个框。
- 预设的高亮跟着**合成后的值**走：手动填 1 小时 30 分，「1.5 时」也会亮起来。
- 空值和 0 严格区分：两个框都空 → `""`（未记录），明确填 0 → `0`。
  store 里 `hasDuration()` 是按 `!== ""` 判定的，把空值落成 0 会让
  「未记录用时」的健康检查漏报。

**顺手合并了四份重复实现。** `formatDuration` 原本有三个文件各写了一份
（`DashboardPage`、`RecordDetailPage`、`ContributionHeatmap`），
和 `utils/recordDisplay.js` 里已有的那份几乎一样，只有空态文案不同。
现在统一到 `recordDisplay.js`，空态文案做成参数。同一个数据在不同页面上
显示成不同样子，是这类 bug 里最难排查的一种。

新逻辑配了 `scripts/test-duration.mjs`（44 项断言）。最要紧的一条是
**split → compose 的往返**：拆成两个输入框再合回去，必须还是原来的数。
不成立的话，用户打开编辑弹窗、什么都不改、直接保存，数据就悄悄变了。
对 17 个取值逐一验证。

### 3. 把「填得少」变成能判断的数字

健康检查里原来只说「有几条没记用时」。数字本身说明不了要不要管 ——
补上占比：「占全部成绩的 34%」。这样才分得清「偶有遗漏」和「一半都没记」。

### 4. 审计脚本自己的两个问题

- **`audit-a11y` 漏审了最主要的录入界面。** 录入表单在首页是收起的，
  要先点「记录成绩」才展开，而它只扫初始状态 —— 于是全站最主要的数据入口
  从来没被审过。给它加了 `prepare()` 步骤，同时 `audit-buttons` 也补上了
  对应的路由（按钮总数 120 → 131）。
- **`--only` 匹配不到时静默跑 0 个路由还报「全部通过」。** Git Bash 会把
  `/` 开头的参数当路径转换（`--only=/` → `--only=C:/.../PortableGit/...`），
  一个都匹配不上，脚本却照样打印 ✓。改成匹配不到就报错退出。
  `verify-ui.mjs` 早就有这个防护，`audit-a11y` 漏了。

新增的「用时」控件也过了审计：两个输入框各有 `aria-label`，
预设按钮在窄屏折成两行后每行只有 19.6px，补了 `min-height: 26px`
（分段控件里按钮紧挨着，拿不到 WCAG 2.5.8 的间距豁免）。

## 第九轮：死 CSS 清理 + 列表顺序稳定性

这一轮的起点是「还有没有能优化的」。没有直接动手，先跑了一遍量测：
`verify-ui` 扫了 48 个「尺寸 × 页面」组合，0 个问题；六张页面截图逐张看过，
版式也都是对的。页面**结构**上已经没什么可挑的了。

于是换个方向找：量体积。

| | 行数 |
|---|---|
| CSS | 11,574 |
| JS | 10,336 |

**CSS 比全部 JS 加起来还大**，而一个纯展示层本来不该这样。这就是这轮的主攻点。

### 1. 先造一把尺子：找「定义了但没人用」的类名

`scripts/find-dead-css.mjs` 扫出 519 个类名里有 107 个从未被引用。
写这个脚本的主要工作量不在扫描，而在**排除假阳性**——不然删掉还在用的类名，
页面不会报错，只会悄悄变样。三类假阳性：

- **模板串拼出来的**：`class="tone-${item.tone}"`、`level-${cell.level}`。
  静态搜 `tone-blue` 永远搜不到。用 `DYNAMIC_PREFIXES` 放行。
- **数据直接给的裸类名**：`:class="item.type"`，toast 用 `info`/`error`/`success`，
  公告用 `feature`/`polish`。用 `DATA_CLASSES` 白名单放行。
- **前缀相同的短名**：`class="mobile-empty-state"` 存在，不代表 `.empty-state` 有人用。
  必须按词边界匹配：

  ```js
  new RegExp(`(?<![\\w-])${escaped}(?![\\w-])`).test(allText)
  ```

  这一条当时差点被我否掉——`grep empty-state` 明明有结果。复查才发现
  **脚本是对的、我的 grep 是糙的**：命中的那次在 `mobile-empty-state` 里面。

顺带加了 `--list`，方便喂给已有的 `prune-css.mjs`：

```bash
node scripts/prune-css.mjs $(node scripts/find-dead-css.mjs --list) --write
```

结果（第一遍，只覆盖非媒体查询部分）：**11,574 → 10,435 行（−1,139）**，
打包后 CSS **160.66 kB → 137.86 kB**，gzip **27.65 kB → 23.99 kB**。
`tablet.css` 一条没删 —— 当时以为「它本来就没有死规则」，
收尾时才发现是修剪器自己的 bug（见第 6 节）。

### 2. 改 CSS 之前，先造好安全网

删类名是「不会报错的改动」，所以先写了 `scripts/diff-shots.mjs`：逐像素比对两组截图。
本机没有 sharp / PIL / numpy / jimp，就用浏览器自带的 canvas —— 零新依赖。

工具本身要先被验证过才敢用：
- **自检**：同一批图对同一批图，报「完全相同」，说明没有随机噪声。
- **灵敏性**：拿两张不同页面对比，报「82.25% 像素不同」，说明确实能测出变化。

中间踩了个坑：canvas 画跨域图会被污染，`getImageData` 直接抛 `SecurityError`。
起因是用 `about:blank` 当宿主页，而它的 origin 是 `null`。改成由工具自己
起一个同源的 `/__blank` 空页面就好了。

### 3. 安全网抓到一个真 bug

比对时发现错题页有 **3.1% 像素**在变（`maxDelta 202`）。一开始以为是噪声，
查下去才发现是真的：**两条种子错题的 `createdAt` 一模一样**
（都是 `2026-10-02T02:28:57.783Z`），而 IndexedDB 的读取顺序每次刷新都不同。

`Array.prototype.sort` 是**稳定**的——比较返回 0 时保持**输入顺序**。
输入顺序不稳定，列表顺序就不稳定。用户看到的现象是「刷新一下顺序就变了」。

修了三处，并且把规则收进 `src/utils/sorting.js`，避免以后再各写一份：

- 种子数据：`sampleMistake` 补上 `daysAgo` 参数，两条错题错开成 −1 / −3 天。
- `sortRecords` / `sortMistakes` / `sortImages`：统一走 `compareByTimeThenId`。
- `RecordsPage.vue` 的 `compareRecords`：五个分支**每一支**都补上 `|| byId(a, b)`。

这里有个必须说清楚的点：**id 兜底只能消除「同一次数据内的不稳定」，
消除不了「数据本身每次都不同」。** 两条种子错题的时间戳完全相同，
兜底就退化成比较随机 UUID —— 排序依然是在掷骰子。
所以真正的解法是让被比较的字段本身有区分度（给种子数据不同的创建时间），
id 兜底只是第二道防线。这句话写进了 `sorting.js` 的文件头。

配了 `scripts/test-sorting.mjs`（15 项断言）。核心不变量是
**「结果与输入顺序无关」**——同一批数据，正序 / 倒序 / 轮转三种输入，
排序结果必须一致。里面还放了一个**对照组**：故意用不带 `byId` 的比较函数，
证明它确实会随输入顺序变。没有对照组的话，这个断言可能只是恰好成立。

### 4. 顺手修的：种子错题没有难度

新装的用户会看到两条错题都写着「难度未填」，像是应用有数据质量问题。
给种子数据补上 `中等` / `困难`。

### 5. 怎么确认「没改坏」

对比清理前的基线，52 张里有 18 张不同。逐类核对完，没有一张是意料之外的：

| 类别 | 张数 | 原因 |
|---|---|---|
| 首页 `_` | 5 | 「连续学习」1 天 → 4 天 |
| 错题页 | 11 | 难度 / 创建时间 / 稳定排序 |
| `records__id` | 2 | 4–52 像素、`maxDelta 1`，纯抗锯齿 |

首页那个数字值得算一遍，因为它看着像回归：

- **改之前**：两条种子错题的 `createdAt` 都是「此刻」，学习日集合 =
  {−8, −6, −4, −2, 今天}。从今天往回走，今天有、昨天没有 → **连续 1 天**。
- **改之后**：错题落在 −1 / −3，集合 = {−8, −6, −4, −3, −2, −1}。
  往回走 −1 → −2 → −3 → −4，−5 断了 → **连续 4 天**。

所以这是种子时间戳修好之后的**正确**结果：demo 数据终于能演示「连续学习」
这个功能了，而不是显示一个看起来像坏掉的 1 天。裁图放大看过，
`1` 和 `4` 的字号 / 字重 / 颜色 / 位置完全一致，只是字形不同。

为此把一次性的裁图脚本扶正成 `scripts/crop-diff.mjs`：`diff-shots` 说
**哪里不一样、差多少**，`crop-diff` 把那一小块**裁出来给你看**。
一个定位、一个定性，配成一对，以后再改 CSS 就有现成的判据。

### 6. 收尾时发现 `prune-css.mjs` 有个静默 bug

第一轮修剪只动了 3 个文件，`tablet.css` 一条都没删。查下去发现是修剪器自己的问题：

```js
const trimmed = prelude.trim();
if (trimmed.startsWith("@")) {   // ← 这里
```

**本项目几乎每个 `@media` 上方都有一行说明注释**，于是 `prelude` 是
`\n/* 说明 */\n@media (...) `，`trimmed` 以 `/*` 开头，判断失败 ——
整个 `@media` 块被当成普通规则**原样拷贝，再也没递归进去**。
`tablet.css` 整份都是 `@media`，所以一条都没删掉，脚本还打印得好好的。

这正是「不会报错的 bug」的典型：修剪器报告「丢规则 0」，看起来像是
「本来就没有死规则」，而不是「我跳过了整个文件」。

修法是把剥注释提到判断之前：

```js
const { trivia, rest } = splitTrivia(prelude);   // 先剥掉前导注释
const trimmed = rest.trim();
```

修完再跑，多出 **8 条规则、37 个选择器**（`tablet.css` 615 → 573 行，
`design-system.css` 顺带丢掉一个被清空的 `@media` 块）。

### 7. 修剪前先独立验一遍死类清单

这次的改动落在媒体查询里，动的是平板 / 手机版式，风险比上一轮高。
所以除脚本自己的判断外，又做了一次**方法上独立**的交叉验证：
把死类清单逐个到**打包产物**（`dist/assets/index-*.js`）里找 ——
模板里用到的类名一定会以字面量出现在编译后的 JS 里。

结果只有 `subject-card` 命中，而它是 `ds-subject-card` 的子串
（正是脚本用词边界要排除的那类假阳性）。清单可信，才动手。

修剪后再跑一遍，死类清单变成**空**——这本身就是幂等性的证明。

### 验证

```bash

npm run check          # 44（用时）/ 72（store）/ 15（排序）/ 5 个弹窗 / 导出 / 无障碍 0 问题
npm run check:buttons  # 131 个按钮，0 报错，0 危险操作漏确认
```

改 CSS 前后各拍一遍 52 张截图逐像素比对（`.verify/pre-media` vs `.verify`）：

```

有差异：2   —— 都是 390/768 的 records__id，52 像素、最大通道差 1
```

另一条同样关键：**同一次构建连拍两次**，只剩 1 张有 52 像素差（`maxDelta 1`）；

最终：CSS 类名 **519 → 411**，死类 **107 → 0**；
CSS 行数 **11,574 → 10,383**；
打包 CSS **160.66 → 136.72 kB**，gzip **27.65 → 23.77 kB（−14.0%）**。

## 第十轮：让它真的能装到手机桌面（PWA 接线）

起因是用户问「想做成手机 App，手机上不用网页，应该怎么办」。
设备是**鸿蒙手机 + iPad**，目标是「先能装到桌面就行」。

结论：**不需要打包原生 App，PWA 就够了** —— 但在这之前它其实是坏的。

### 1. 症状与真因：manifest 从来没被引用

`public/manifest.webmanifest` 和 `public/sw.js` 都写好了，看起来「PWA 已经做了」。
但 `index.html` 里**一个 `<link>` 标签都没有** —— 没有引用 manifest。

浏览器不知道 manifest 存在，于是 `display: standalone` 不生效、快捷方式不生效、
图标不生效、也不会有安装提示。手机上打开就是**带地址栏的普通网页**。

这正好解释了用户的感受。**「文件在不在」和「浏览器有没有看见」是两回事**：
`ls public/` 会告诉你「manifest 有了」，从而得出「PWA 做好了」的错误结论。

### 2. 另外两个会直接打脸的问题

- **iOS 不认 SVG 主屏幕图标**。原来只有 `icon.svg`，iPad 上
  「添加到主屏幕」会得到一个空白方块（退化成网页截图）。
  本机没有 sharp / PIL，所以用浏览器 canvas 光栅化
  （`scripts/gen-icons.mjs`，用 Blob URL 避免画布污染），
  产出 180 / 192 / 512 / 512-maskable 四个 PNG。
  其中 iOS 那张必须**全出血**（圆角改成直角）—— 透明圆角会被 iOS 填成黑色。
- **快捷方式 URL 与路由模式不匹配**。manifest 里写的是 `/mistakes`，
  而路由用的是 `createWebHashHistory`，正确地址是 `/#/mistakes`。
  不改的话，长按图标弹出的「新增错题」会落到首页。

### 3. 新增 `scripts/check-pwa.mjs`

按 Chrome 的「可安装」判定条件逐条验：引用 manifest、manifest 合法、
name / start_url / display、192 与 512 图标、**图标实际像素尺寸与声明一致**、
apple-touch-icon 存在且不是 SVG、SW 真的激活、快捷方式与路由模式匹配。

并做了**反向验证**：临时从 `dist/index.html` 里删掉 manifest 那一行，
脚本立刻报「引用了 manifest —— PWA 不会生效」；恢复后全绿。
没有反向验证的检查，无法证明它真的会失败 —— 这条和第九轮的
「对照组」是同一个道理。

`check:pwa` 已并入 `npm run check`。

### 4. 全屏运行的顶部安全区

用户确认走 PWA（鸿蒙手机 + iPad，只要装到桌面），并问「做成 app 还要打开网页吗」——
不是。装到桌面后点图标是**全屏**打开的，没有地址栏、没有浏览器界面，
「打开网页」只是安装那一次的动作。

但全屏运行暴露了一个之前没人注意到的问题：
**`env(safe-area-inset-*)` 只处理了底边和左右，漏了 top。**
配合 `viewport-fit=cover`，iPad 全屏打开时侧栏的品牌标识和顶栏会被状态栏（时钟/电量）压住。

修的时候踩到一个层叠的坑：`.workspace` 的 padding 在 `main.css` 里有**十几处**
互相覆盖（不同断点各写一份），直接改基础规则会被后面的规则盖掉。
所以改加在 `body` 上 —— 一处生效、不跟任何断点打架。
侧栏是 `position: fixed`（不跟着 body 走），单独在它自己身上补。
吸顶的 `.topbar` 则把 `top` 从 `0` 改成 `env(safe-area-inset-top)`。

`env()` 在普通浏览器里取 0，所以桌面端完全没变化。用探针确认过改动后的计算值：
`body padding-top = 0px`、`topbar top = 0px`、`sidebar padding-top = 14px` —— 全是改动前的原值。

至于「真机上到底管不管用」，没法验，就**模拟**：
把打包后的 CSS 里 `env(safe-area-inset-top,0px)` 临时换成 `24px`（iPad 状态栏高度），
重新截图 —— 品牌标识和顶栏确实都落到 24px 以下，而侧栏的深色背景依然铺到顶端
（沉浸感没丢）。验证完再还原。

### 5. 顺带修掉一个既有的断点冲突

- `main.css` 的 `@media (max-width: 820px)` 把 `.topbar` 设成 `flex-direction: column`（手机版式）
- `tablet.css` 的 `@media (min-width: 768px) and (max-width: 1023px)` 给 `.topbar-title`
  设了 `flex: 1 1 240px`（按 row 写的）

**768–820px 这一段两个媒体查询同时命中**，于是那个 `240px` 从「宽度」变成了「高度」，
顶栏被撑到 **313px** —— 差不多占掉三分之一屏。而 768×1024 / 810×1080
正是常见的 iPad 竖屏尺寸，用户一装就会看到。

在平板规则里显式写回 `flex-direction: row`，顶栏 **313 → 122px**。
手机端（390×844）实测与改动前逐像素一致，确认没被牵连 ——
平板那条规则要求 `min-height: 600px`，横过来的手机（高 390）本来就不命中。

### 验证

```bash
npm run check          # 44 + 15 + 72 断言、5/5 弹窗、导出、PWA、无障碍 0 问题
node scripts/verify-ui.mjs --sizes=768x1024,390x844   # 0 个问题
```

## 第十一轮：填了一半的表单不能被静默丢掉

起因还是那句「还有没有可以优化的了，交互体验这方面的」。
上一轮刚给弹窗加了「返回手势关闭」，正好把误关的概率推高了 ——
手机上从边缘滑一下，原本是「返回」，现在变成了「关掉表单」。

### 1. 先量：五条关闭路径全是静默丢弃

录入表单散在 **5 个地方**（首页内联、成绩列表内联面板、成绩详情编辑、
错题列表内联、错题详情编辑）。写了个探针逐条点，结果一致：

```
① 点「收起录入」:    表单还在? 否  确认框? 否  => ★ 静默丢弃
② 点 section 的关闭按钮: 表单还在? 否  确认框? 否  => ★ 静默丢弃
③ 切到「科目」路由:  表单还在? 否  确认框? 否  => ★ 静默丢弃
```

录入一条成绩要填科目、卷名、分数、用时、备注；错题还要传图、跑一次 AI 解析。
丢掉一次的成本不低，而且**一点提示都没有**。

（探针第一版还测错过一次：以为首页表单是弹窗，去按 Escape、找「关闭」按钮，
结果报出「有保护」。读了 `DashboardPage.vue` 才发现它是内联的 `DsSection`，
重写成三条真实路径才量出上面这个结果。）

### 2. 做成全局的，而不是每个页面各写一遍

表单出现在 5 处、横跨新建和编辑两种模式，逐个页面写 `onBeforeRouteLeave` 必然漏。
而「换页时保护」这件事本身**只有路由层能统一兜住**。所以：

- `composables/useUnsavedChanges.js`：一个 token 集合 + `confirmDiscardChanges()`
- 表单只管把「我脏了」登记进来（`useUnsavedForm` / `useUnsavedFields`）
- 关闭侧调 `confirmDiscardChanges()`；换页由 `router.beforeEach` 统一拦

用 token 集合而不是一个布尔值：同一时刻可能不止一个表单挂着，用布尔值的话
先关掉的那个会把标记清成 `false`，另一个就漏保护了。

### 3. 「脏」怎么判：两个都想当然的做法都是错的

**不能看「字段有没有非空」** —— 科目、满分、卷型、日期都是自动填的，
而且科目表是**异步**来的（`store.load()`）。挂载那一刻快照基线，拿到的是空值，
等自动填充一跑，表单一打开就是「脏」的。

**也不能只看「有没有触发过 input 事件」** —— 错题的 AI 解析是**代码写进去的**
（`analyzeWithAi` 直接改 `form.title / questionText / analysis`），一个事件都没有；
上传的图片同理。而这些恰恰是花了一次 AI 调用换来的、最不该丢的内容。

最后是反过来做：让表单在**自动填充结束**时调 `markPrefill()` 记下当时的字段值
当基线，之后只要用户动了其中一个字段就算脏。`markPrefill()` 内部**已经脏了就不再
挪基线** —— 否则一次异步的自动填充会把基线盖到用户输入上，表单凭空变回「没改过」。

「哪些字段算用户输入」是逐个挑的，不挑自动填的那些：

| 表单 | 判脏的字段 | 额外 |
| --- | --- | --- |
| `RecordForm` | 卷名、习题册、页码、题号、得分、用时、备注 | — |
| `MistakeForm` | 标题、知识点、题干、解析、下次复习 | 已选图片数 > 0 |

### 4. 一个容易漏的时序坑：刚存完反而弹确认框

保存成功后表单会 `resetDirty()` 再 `emit("saved")`，父组件**同步地**把表单关掉、
顺手问一句 `confirmDiscardChanges()`。而 `watch` 默认是 `pre` 刷新（异步的），
那一刻 `dirtyTokens` 里还留着这个 token —— 结果是**刚存完反而弹一个「放弃未保存的内容」**。

改成 `flush: "sync"`，让注销发生在 `resetDirty()` 返回之前。
审计里专门留了一条「保存成功后不能反问一句」盯着它。

### 5. 反直觉的一条：**返回 / 前进不拦**

换页守卫拦「点侧栏链接」这类前进导航，效果很好（取消留在原页、放弃真的换页）。
但「浏览器返回」这一种**必须放行**，因为拦了会更糟：

这种导航是浏览器**先把地址改掉**、再通知我们的。想中止，就得靠 vue-router
自己补一次 `history.go()` 退回去。而它算该退多少用的是 `history.state.position`，
那个值在 `buildState` 里是拿 **`history.length`** 记的 —— `history.length` 只增不减，
而本项目的弹窗每次打开都会 `pushState`（见 `useDialogA11y`）。压过几次之后这个差值就偏了。

实测到过：在填了一半的表单上按返回、再选「继续编辑」，地址栏退到了**上一个**页面
（`#/subjects`），画面却还停在首页 —— **地址和画面不一致**，比不拦更难理解。
所以守卫里遇到 `popstate` 来的导航直接放行，审计改成守「地址和画面必须一致」这个不变量。

### 6. 守卫里弹的确认框不能动历史栈

修上面那条时又挖出一层：`confirmDiscardChanges()` 用的确认框也走 `useDialogA11y`，
打开时同样会 `pushState`。它一压一弹，正好把 vue-router「导航中止就退回原地址」
的那次 `go()` 搅乱 —— 表现是**点了「放弃」反而没换页**（实测）。

给 `DsModal` / `useDialogA11y` 加了一个 `historyEntry` 选项（默认开），
`useConfirm` 透传 `noHistory`，只有「路由守卫里弹的确认框」传 `false`。
普通确认框（删除之类）的行为不变，返回手势照样能关掉它。

### 7. 顺手挖出的第二个 bug：「基于本成绩新增错题」是个空动作

成绩列表每行有个图标按钮，`aria-label` 是「基于本成绩新增错题」。
点下去是 `router.push("/mistakes?recordId=xxx")` —— 但 `MistakesPage`
**根本没读这个 query**（`readMistakeFilters` 只认 q/subject/chapter/status/difficulty/sort），
表单也不开。结果是：落到错题列表上，筛选没变、表单没开，**看起来像按钮坏了**。
要再点一次「新增错题」才看得到预填的标题。

修法：
- `MistakesPage` 读到 `recordId` 就**把表单打开**，然后立刻把它从地址里摘掉
- `MistakeForm` 不再自己去读 `route.query`，改由 prop 传入

第二步是必须的：这个页面一改筛选就会 `replace` 掉整个 query，顺手把 `recordId`
冲走；而 `MistakeForm` 的填充 watcher 依赖它，一冲就会重灌一遍表单，
把已经填好的标题清空。改成 prop 之后就与地址无关了。

### 8. 补刀：填充 watcher 会把用户正在输入的内容冲掉

上面把「关闭路径」都堵上了，但表单**内部**还有一个更隐蔽的丢法：
`MistakeForm` / `RecordForm` 的填充 watcher 是**无条件重灌**的。

`MistakeForm` 的依赖里有 `store.records.length` —— 后台同步拉回一条成绩就会变；
`RecordForm` 的依赖里有 `store.visibleSubjects` —— 那是个 computed，每次重算都是新数组，
科目表被重新赋值就会变。两种变化都跟「表单的源」无关，却会把表单整个覆盖一遍。

实测（临时把 store 挂到 window 上制造这两种变化，量完就撤）：

```
A. 错题表单：填到一半时后台同步拉回一条成绩
   输入后:  标题="我正在输入的标题"  知识点="我正在输入的知识点"
   records.length: {"before":4,"after":5}
   之后:    标题=""                  知识点=""            ← 冲掉了

B. 成绩表单（编辑态）：改到一半时科目表被重新赋值
   改完:    卷名="我改过的卷名"      备注="我改过的备注"
   visibleSubjects 重算: 4 个科目
   之后:    卷名="同步回来的卷子"    备注=""              ← 冲掉了
```

这里暴露了上面第 3 节的一个疏漏：`markPrefill()` 的「脏了就不挪基线」
**只保护了判脏标记，没保护内容** —— 内容照样被覆盖，于是表单仍然显示「有未保存内容」，
关的时候白问一句，而内容其实早就没了。

修法是把保护点前移：**只在「源」变了的时候才重新灌**。
源 = 编辑态 `props.mistake` / `props.record` 的 id，新建态是 `props.sourceRecordId`。
源没变就一个字段都不动（只补一个「还没填上」的默认科目）。

顺带处理一个异步边界：直接打开 `/mistakes?recordId=xxx` 时成绩表可能还没加载完，
那次先不灌、等它到了再灌 —— 但**只在表单还没脏的时候重试**，否则又会变成一次覆盖。

于是 `markPrefill()` 就没人用了（它的活儿由「别重灌」接走了），删掉。

**没能加自动化回归**：这两个触发条件都只有云同步才碰得到（`records.length` 变化
需要别处增删成绩，`visibleSubjects` 重算需要改科目），离线审计里点不出来。
所以只验了「没改坏」（9 个场景照旧全绿）加上直接打开 `?recordId=` 的路径。
这条是**靠构造修好的，不是靠断言守住的**，记在这里备查。

### 验证

```bash

npm run check:buttons    # 全绿
node scripts/verify-ui.mjs
```

`scripts/audit-interaction.mjs` 从 6 个场景扩到 9 个，新增的三组都做了**反向验证**：

- 场景 7：收起要拦（3 条路径）+ **什么都没填时不能弹确认框**
- 场景 8：侧栏换页要拦、取消留在原页、放弃真的换页；按返回后地址和画面必须一致
- 场景 9：那个按钮要真的把表单打开、且用完把 `recordId` 摘掉

场景 7 的反向验证不是装饰：第一版就是因为它才暴露出「自动填的科目被当成用户输入」。
另外每个场景都从 `reload()` 开始 —— `goto` 到只有 hash 不同的地址时浏览器可能只做
同文档导航，上一个场景的组件状态会串进来（一开始就是这么误报了一条）。

## 第十二轮：把 `public/legacy/` 请出仓库

### 1. 起因：本来只想清个死重

`public/legacy/` 是 6 月 7 日迁移前的静态版本，`README.md` 写着「保留作为迁移参考」。
本来只想问一句「要不要顺手清掉这 108K」，量了一下发现它不只是死重。

### 2. 量出来的事实

- Vite 把 `public/` **原样拷进 `dist/`** → 本地 `npm run build` 之后，预览服务器上
  `/legacy/index.html` 和 `/legacy/app.js` 都是 HTTP 200（13102 B / 40634 B）。
  **从源码构建出来的产物里都有这 108K。**
- `legacy/reset.html` 是个迁移期的「清缓存」页，它做两件事：
  1. `navigator.serviceWorker.getRegistrations()` → 注销本站**所有** SW
  2. `caches.keys()` → 删掉**所有** Cache Storage

  然后 `location.replace("./?v=reset-57bc308")` 跳回首页 —— 把破坏掩盖掉。
- 新版 `public/sw.js` 的预缓存（`/`、manifest、5 个图标）正好存在那块 Cache Storage
  里 → 谁访问到 `/legacy/reset.html`，就会**注销新版 SW + 清掉新版预缓存**，
  打掉第十轮的成果。下次加载会重新注册，所以是**静默降级**，用户看不出原因。
- `legacy/index.html` 引用 `./manifest.webmanifest`，而该文件不在 `public/legacy/`
  里（只有 7 个文件）→ 404，旧应用本身就是坏的。
- `legacy/db.js` 用 localStorage `exam-11408-state-v1`，与新版的 key 不同
  → **不会污染新数据**，所以这不是数据安全问题。

### 3. 一次差点写错的推断：生产上到底够不够得着

先看 `vercel.json`：有一条兜底路由 `/(.*)` → `/index.html`。但 `/icon-192.png` 和
`/manifest.webmanifest` 都没有单独路由，却确实能正常访问（第十轮验证过图标能装上）
→ 于是推断「静态文件优先于兜底路由，所以 `/legacy/reset.html` 在生产上会被当真文件返回」。

**这个推断是错的。** 漏看了一个文件：`.vercelignore` 第一行就是 `public/legacy`。
`.vercelignore` 决定哪些文件**上传**到 Vercel —— 它不上传，Vercel 侧构建时
`public/legacy` 根本不存在，`dist/legacy` 也就不会被生成。
**所以线上从来没有服务过 `/legacy/`，那个隐患在生产上一直是够不着的。**

漏看的原因值得记一笔：第一次搜引用用的是 `rg`，而它**默认跳过隐藏文件**，
`.vercelignore` 是 dotfile，被静默略过了，于是得出了「只有 README 引用了它」的错误结论。
`git grep` 会搜已跟踪的 dotfile，这次是靠它兜住的。

修正后的结论：这 108K 与 `reset.html` 的隐患**只存在于本地 / 自建 / 非 Vercel 部署**，
生产（Vercel）不受影响。删它依然值得 —— 死代码、本地隐患、外加能顺手删掉一行
已经没用的 `.vercelignore` 配置 —— 但**不能**说成「打掉了线上的 PWA」。

### 4. 删掉，并且验证删干净了

`git rm -r public/legacy`（7 个文件），改掉 `README.md` 里那行，
并删掉 `.vercelignore` 里已经没用的 `public/legacy`。

验证的关键是**不能只看状态码**：删完之后 `/legacy/reset.html` 仍然返回 200 ——
因为静态服务器对不存在的路径会兜底到 SPA 外壳。真正要看的是**返回的内容**：

```bash
curl -s http://127.0.0.1:4183/legacy/reset.html | grep -c "resetAppCache"  # → 0
curl -s http://127.0.0.1:4183/legacy/reset.html | diff - dist/index.html   # → 无输出（逐字节相同）
```

`resetAppCache` 数到 0、且返回体与 `dist/index.html` 逐字节相同（都是 2011 B，
引的是当前产物 `assets/index-U1LmRZYl.js`）→ 旧页面确实不再被服务。

### 验证

```bash
npm run check    # 全绿；PWA 段仍报「Service Worker 已激活」
```

删的是纯静态文件、没有任何脚本引用它（`supabase.js` 里的 `legacyError` /
`toLegacySubjectRow` 只是同名，指的是数据库列映射，与这个目录无关），所以是惰性改动 ——
PWA 检查全绿反过来证明没有误伤第十轮的接线。

## 第十三轮：错题列表的规模，和首屏不该背的代码

起因是用户问「还有哪里可以优化」。这一轮全程**先量后改**，每条都留了改前 / 改后的数。

### 1. 错题列表：两个独立的问题叠在一起

`MistakesPage` 把筛选结果**整份**渲染、没有上限；搜索框又 `v-model` 直连
`filters.keyword`，每敲一个字就重算全量筛选并重渲染所有卡片。

实测（桌面 1440×900）：

| 错题数 | DOM 节点 | 渲染耗时 |
|---|---|---|
| 50 | 1,451 | 27ms |
| 200 | 5,051 | 65ms |
| 500 | 12,251 | 148ms |
| 1000 | 24,251 | 278ms |

改法两处都向成绩页看齐（它两样本来就有）：

- 按 **8 条/页**分页，复用现成的 `.pager` 样式
- 搜索框绑草稿 `keywordDraft`，**260ms 防抖**之后才写进 `filters`
- 换筛选回第 1 页；结果变少时把页码夹回有效范围

改后：**任何条数都是 460 个节点、8 张卡片。**

### 2. 首屏背了所有页面的代码

router 里 8 个页面全是静态 import → 入口 chunk 628K raw / 190K gzip，
而用户每次只看得见其中一页。改成 `() => import()`。

**但只改这一处是负收益**：跨页面共享的 lucide 图标被切成一堆 0.14K 碎片，
请求数从 4 涨到 16，省下的字节全被请求数吃回去。于是加 `manualChunks`。

这里有个**量出来的教训**：第一版我还把 vue / supabase / dexie 各自拆成
`vendor-*` 块 —— 结果它们**全都是首屏就要的**，字节一个没省，请求数却从 4 涨到 14。
拆 vendor 只在「vendor 不必全量加载」时才有意义，这个应用不满足。
改成**只并图标**，其余交给 Vite 默认策略。

最终（gzip 传输量，含 css）：

| 路由 | 改前 | 改后 |
|---|---|---|
| `/#/` | 214.2K | **191.4K**（js 190.1K → 167.3K）|
| `/#/records` | 214.2K | 197.4K |
| `/#/mistakes` | 214.2K | 183.2K |
| `/#/backup` | 214.2K | 174.4K |
| `/#/subjects` | 214.2K | 176.3K |

即**少 12%~21% 字节，代价是请求数变多**（HTTP/2 多路复用能吸收一部分）。
说实话收益没有一开始预期的大 —— 因为页面代码本身就不大，
真正的大头是 vendor，其中 **supabase + dexie 就占 81K gzip**。

### 3. 差点做错的一件事：以为能「不加载 Supabase」

既然 vendor 是大头，很自然会想：supabase-js 只在登录 / 同步时用，
改成懒加载不就能省 81K gzip？

查了调用点才发现不行：store 初始化时（`load()` 里）就 `await getSession()`
恢复登录态、并 `subscribeAuth()` 订阅鉴权变化 —— **Supabase 在启动路径上**。
改成动态 import 只会把下载推到首屏之后，字节一分不少，
却要动鉴权 / 同步这条最难验证的链路（沙箱连不上 Supabase，测不了）。
所以**没做**，只把结论记下来。

### 4. Service Worker：缓存只增不减，还缓存了别人家的东西

`sw.js` 的 fetch 对每个 GET 都 `cache.put`，而且**不过滤 origin** ——
Supabase / R2 的跨域响应也一起塞进 Cache Storage；activate 又只删**别的**
cache 名、不动自己，于是带 hash 的旧资源永不淘汰，只能靠手改 `CACHE_NAME`。

改法：跨域直接放行；只有 `/assets/`（带内容 hash，内容变了名字就变）走 cache-first；
其余（HTML / 图标 / manifest，名字固定）保持 network-first；只缓存 200。
`CACHE_NAME` 升到 **v4**，让旧条目在 activate 时被清掉。

### 5. 故意没做的两件事

- **`package.json` 加 `"type": "module"`**：能消掉跑测试时的
  `MODULE_TYPELESS_PACKAGE_JSON` 警告，语义上也正确（所有 `.js` 都是 ESM）。
  但它会改变 Node 对 `api/*.js` 的解析 —— 那是线上的 serverless 函数，
  管着登录、同步、R2 上传和 AI 解析。**沙箱连不上 Vercel，这类运行时回归
  不会体现在部署状态里，只会在线上炸。** 为了一行日志不值得。
- **把 `vite` / `@vitejs/plugin-vue` 挪到 devDependencies**：纯卫生问题，
  没有用户可见收益，却有可能让 Vercel 构建装不到 vite。

另外还**撤回了自己提过的一条建议**：给 Supabase 加 `preconnect`。
查了 `shouldUseSupabaseProxy()` 才发现默认走**同源代理**
（`/api/supabase-proxy`），压根没有跨域握手可以省。

## 第十四轮：那四条「从没记过的成绩」是怎么来的

用户截图问：「为什么每次同步都会出现这四个原本没有记录的东西」。
四条成绩是 `408 综合模拟 01` / `数一 模拟 01` / `英一 阅读专项` / `政治 选择题套卷`，
日期 09-25、09-27、09-29、10-01。

### 1. 先确认它不是用户数据

这四条的名字、分数、用时、备注和 `createDemoRecords()` 里的常量**逐字相同**；
日期正好是「今天 − 8 / −6 / −4 / −2 天」（种子数据就是这么算的）。
所以这不是同步写坏了数据，是**演示种子数据漏进了账号**。

### 2. 泄漏链路

```
seedIfEmpty()        空库就无条件灌 4 条成绩 + 2 道错题
   ↓
mergeCloudEntries()  「本地有、云端没有」→ 标 pendingSync
   ↓
retryUnsyncedData()  上传 —— 演示数据被「洗白」成云端真实记录
   ↓
runCloudLoad()       云端优先合并，本地演示数据不会被清掉
                     → 每台设备、每次同步都拉回来
```

还有一层自我复制：用户删掉之后本地 `records` 又空了，
下一次 `load()` 再灌一遍、再传一遍 —— 所以是「删不掉」。

### 3. 四层修复

| 层 | 规则 | 位置 |
|---|---|---|
| 1 | 云端模式**不灌**演示数据 | `load()` 传 `seedDemo: !isSupabaseConfigured` |
| 2 | 只有 `records` 和 `mistakes` **都**空才灌 | `seedIfEmpty()` |
| 3 | 灌过就不再灌（`localStorage` 标记） | `hasSeededDemo()` |
| 4 | 演示数据**永不上传**（合并 + 队列双闸门） | `mergeCloudEntries()` / `retryUnsyncedData()` |

第 2 条修的是一个附带 bug：以前两张表各自判断，
把错题删光会被**单独补种**两道回来。

### 4. 已经在云上的那四条怎么办

光堵源头不够 —— 它们已经在用户的云端库里了，登录就会被拉回来。
所以加了 `purgeDemoEntries()`：云端加载后清一次，并且**从云端删掉**（否则下次还会回来）。

判定用**内容指纹，不看 id**：

- 老版本用 `crypto.randomUUID()` 生成 id，那批漏出去的记录认不出前缀，只能靠内容兜；
- 反过来，如果拿 `demo-` 前缀当标记，用户改过一条演示数据之后它**永远不同步**了 ——
  改过的数据反而丢。只看内容就没这个问题。

指纹是「科目 + 名称 + 分数 + 满分 + 用时 + 备注」六个写死的常量拼起来，
真实数据撞不上。用户动过任何一项（比如改了分数），指纹不再命中，
就按真实数据保留。删之前照例进回收站，24 小时内还能恢复。

### 5. 顺带挖出一个测试桩的 bug

`test-store.mjs` 里新加的种子断言一开始是失败的：

```
FAIL  显式开启后灌入 4 条演示成绩      实际 0  期望 4
```

查下来错的**不是源码，是测试桩**：`stubDatabase` 的 `write()` 用
`rows.set(name, [...values])` **换掉了数组**，而各表方法是闭包捕获的旧数组 ——
于是 `db.records.count()` 和 `dbStub.read()` 各看各的表，
断言实际是在一个「幻影数据库」上跑。`seedIfEmpty` 看到 `count() = 2`，
正确地判定「库不空、不灌」，测试却读到 0。

改成原地替换（`table.length = 0; table.push(...)`），并补了一节**测试桩自检** ——
桩是测试的地基，地基错了上面所有结论都不可信。
另外给 `db.transaction` 补了桩（`replaceAllData` 走它，Node 里没有 IndexedDB）。

### 6. 连锁反应：三个审计脚本一直在白拿演示数据

修完之后 `npm run check` 挂了三个脚本，报的都是「数据没了」：

- `check-dialogs.mjs`：5 个弹窗里 3 个打不开（导出、合成、删除都围绕记录）
- `check-export.mjs`：列数断言失败（它只塞 3 条英语真题，另外 4 组靠演示数据凑）
- `audit-interaction.mjs`：搜索「模拟」没结果、找不到「基于本成绩新增错题」按钮

这不是回归，是它们**一直在依赖一件不该依赖的事**：演示数据是产品功能，不是测试夹具。
三个脚本现在各自往 IndexedDB 里塞自己的数据（照 `check-export` 已有的做法）。

### 7. 一个要说清楚的行为变化

生产构建里 `.env` 配了 Supabase，所以 `isSupabaseConfigured` 为真 ——
**首次打开不再有演示数据，是空列表**。纯本地构建（没配 Supabase）行为不变，仍然灌一次。

这是有意的：云端账号里不该出现用户没创建过的记录。
代价是新用户第一次打开看到的不是「有内容的示例」，而是空状态。
